## 1. 개요

### 배경

사이드바 재구조화(sidebar-restructure) Plan에서 공정관리(`/processes`)가 최상위 메뉴로 확정되었다. 사업계획서 p.42는 공정관리 하위에 5개 기능을 정의한다. 현재 구현된 `/processes` 경로는 단조/열처리 페이지로 플레이스홀더 수준이며, 5개 하위메뉴 모두 미구현 상태다.

### 목적

- 공정별 생산 실적을 체계적으로 수집하여 목표 대비 실적을 실시간 가시화한다.
- 공정 데이터 이상 감지를 통해 불량 발생 전 선제 조치를 가능하게 한다.
- 작업 조건 표준화로 작업자 간 편차를 최소화하고 품질 일관성을 확보한다.
- Heat No. 기준 공정이력 추적으로 공정-품질 관계 분석 기반을 마련한다.

### 범위

| 항목 | 포함 여부 |
|------|-----------|
| 공정실적관리 CRUD (`/processes/results`) | 포함 |
| 공정 데이터 모니터링 조회 (`/processes/monitoring`) | 포함 |
| 작업조건관리 CRUD (`/processes/conditions`) | 포함 |
| 공정이력조회 조회 (`/processes/history`) | 포함 |
| 공정데이터 분석 조회 (`/processes/analysis`) | 포함 |
| 설비 PLC/센서 실시간 수집 드라이버 개발 | 제외 (설비 인터페이스 팀 별도 계획) |
| AI 예측 모델 훈련 파이프라인 | 제외 |

## 2. 하위메뉴별 사용자 스토리

### 2-1. 공정실적관리

**AS-IS**: 공정별 생산 실적이 종이 일보로 기록되어 목표 대비 실적 비교에 수작업 집계가 필요하다.

| ID | 사용자 스토리 | 완료 조건 |
|----|------------|---------|
| US-01 | 공정 담당자로서 공정 완료 후 실적(수량, 불량수, 작업시간)을 입력하여 생산 이력을 축적하고 싶다. | 실적 등록 후 목표 대비 실적 비율(%)이 즉시 갱신된다. |
| US-02 | 생산 관리자로서 공정별·일별·주별 실적을 목표와 비교하여 생산 계획 달성 여부를 파악하고 싶다. | 공정별 달성률 요약 테이블이 1초 이내 렌더링된다. |
| US-03 | 공정 담당자로서 잘못 입력한 실적 데이터를 수정하고 싶다. | 수정 이력이 audit_log에 기록된다. |

### 2-2. 공정 데이터 모니터링

**AS-IS**: 설비별 공정 파라미터(온도, 압력, 속도 등)가 분산 저장되어 이상 여부를 실시간으로 확인하기 어렵다.

| ID | 사용자 스토리 | 완료 조건 |
|----|------------|---------|
| US-04 | 설비 담당자로서 실시간 공정 데이터를 모니터링하여 설정값 벗어남(이상)을 즉시 인지하고 싶다. | 관리 한계선(UCL/LCL) 초과 데이터 포인트가 시각적으로 강조(빨간색)된다. |
| US-05 | 생산 관리자로서 특정 설비·기간의 공정 데이터 추이를 조회하여 품질 이슈 원인을 분석하고 싶다. | 시계열 차트가 TimescaleDB 쿼리로 렌더링되며, 기간 필터가 동작한다. |
| US-06 | 공정 엔지니어로서 이상 감지 이벤트 목록을 확인하여 조치 이력을 관리하고 싶다. | 이상 감지 이벤트 목록이 최신순으로 표시된다. |

### 2-3. 작업조건관리

**AS-IS**: 공정별 표준 작업 조건이 엑셀 문서로 관리되어 작업자별 설정값 차이가 불량의 원인이 된다.

| ID | 사용자 스토리 | 완료 조건 |
|----|------------|---------|
| US-07 | 공정 엔지니어로서 공정 유형별 표준 작업 조건(온도, 압력, 시간 등)을 시스템에 등록하고 싶다. | 작업 조건 등록 후 공정 실적 등록 화면에서 해당 조건이 참조 표시된다. |
| US-08 | 공정 엔지니어로서 기존 작업 조건을 수정하여 표준을 개정하고 싶다. | 수정 시 이전 버전이 보존되고 변경 이력이 기록된다. |
| US-09 | 작업자로서 현재 공정에 적용된 표준 작업 조건을 조회하여 설정값 기준을 확인하고 싶다. | 작업 화면에서 현재 적용 조건이 1-click으로 조회된다. |

### 2-4. 공정이력조회

**AS-IS**: 품질 불량 발생 시 해당 제품의 공정 이력을 찾기 위해 여러 시스템을 수작업으로 조회해야 한다.

| ID | 사용자 스토리 | 완료 조건 |
|----|------------|---------|
| US-10 | 품질 담당자로서 Heat No.를 입력하여 해당 제품이 거친 전체 공정 이력을 순서대로 조회하고 싶다. | Heat No. 검색 결과가 공정 순서대로 정렬되어 1초 이내 반환된다. |
| US-11 | 공정 엔지니어로서 공정이력과 검사 결과를 동시에 조회하여 공정 파라미터와 품질의 상관관계를 분석하고 싶다. | 공정이력 상세 화면에서 연관 검사 결과로 이동하는 링크가 제공된다. |
| US-12 | 관리자로서 특정 기간·공정 유형 기준으로 이력을 검색하여 품질 이슈 패턴을 파악하고 싶다. | 기간, 공정 유형, Heat No. 복합 필터가 동작한다. |

### 2-5. 공정데이터 분석

**AS-IS**: 공정 데이터가 수집되지만 분석 도구가 없어 데이터 기반 의사결정보다 경험 의존도가 높다.

| ID | 사용자 스토리 | 완료 조건 |
|----|------------|---------|
| US-13 | 생산 관리자로서 공정별 OEE(설비 종합 효율) 지표를 확인하여 설비 효율 개선 포인트를 파악하고 싶다. | OEE = 가용률 × 성능률 × 품질률 공식 기반 산출값이 공정별로 표시된다. |
| US-14 | 품질 담당자로서 공정 파라미터와 불량률 간 상관관계를 분석하여 품질 개선 조치를 취하고 싶다. | 산점도 또는 상관계수 기반 분석 결과가 시각화된다. |
| US-15 | 경영진으로서 공정별 생산성 지표(단위 시간당 생산량, 재작업률 등)를 종합 대시보드에서 확인하고 싶다. | 공정데이터 분석 페이지에서 주요 KPI 카드가 일목요연하게 표시된다. |

## 5. 구현 우선순위

### 이터레이션 1 (Must Have — 핵심 CRUD 및 Traceability)

| 순서 | 작업 | 대상 하위메뉴 |
|------|------|-------------|
| 1 | `process_results` 테이블 스키마 확인 및 마이그레이션 | 공정실적관리 |
| 2 | 공정 실적 CRUD API 구현 및 달성률 계산 로직 | 공정실적관리 |
| 3 | 작업 조건 CRUD API 구현 (버전 이력 포함) | 작업조건관리 |
| 4 | Heat No. 기준 공정이력 조회 API 구현 (Traceability) | 공정이력조회 |

### 이터레이션 2 (Should Have — 모니터링 및 분석)

| 순서 | 작업 | 대상 하위메뉴 |
|------|------|-------------|
| 5 | 설비별 시계열 공정 데이터 조회 API (TimescaleDB 쿼리 최적화) | 공정 데이터 모니터링 |
| 6 | UCL/LCL 기반 이상 감지 이벤트 목록 API | 공정 데이터 모니터링 |
| 7 | OEE 산출 API 구현 | 공정데이터 분석 |
| 8 | 공정이력-검사결과 연계 조회 API | 공정이력조회 |

### 이터레이션 3 (Could Have)

- 파라미터-불량률 상관관계 분석 API
- 이상 감지 실시간 알림 (WebSocket)
- 분석 결과 내보내기 (CSV/PDF)

### 완료 기준 (Acceptance Criteria)

- [ ] 5개 하위메뉴 라우트(`/processes/results`, `/processes/monitoring`, `/processes/conditions`, `/processes/history`, `/processes/analysis`)가 사이드바에서 접근 가능
- [ ] 공정 실적 등록 후 달성률(%) 즉시 갱신 확인
- [ ] Heat No. 입력 시 1초 이내 전체 공정이력 순서 조회
- [ ] 작업 조건 수정 시 버전 이력 보존 확인
- [ ] 이상 감지 이벤트(UCL/LCL 초과) 목록 조회 동작
- [ ] OEE 산출값이 가용률 × 성능률 × 품질률 공식 기반임을 단위 테스트로 검증
- [ ] 모든 데이터 변경이 audit_log에 기록
