> **요약**: 사업계획서 p.42 기반 사용자/시스템관리 모듈의 4개 하위메뉴 기능 정의 — 사용자 관리(RBAC), 로그 관리(감사 로그), 알림 설정, 시스템 설정
>
> **작성자**: Product Manager
> **작성일**: 2026-05-21
> **최종수정**: 2026-05-21
> **상태**: Draft

## 1. 개요

### 배경

사업계획서 p.42에 사용자/시스템관리 모듈의 4개 하위메뉴가 정의되어 있다. 현재 사이드바에 "사용자/시스템관리" 최상위 메뉴는 존재하지만 하위메뉴 구조와 각 기능의 상세 요구사항이 미정의 상태이다. 기존 DB 스키마에는 `users`, `roles`, `audit_logs`, `notifications` 테이블이 존재하여 이를 기반으로 기능을 구현한다.

### 목적

- 사용자/시스템관리 모듈의 4개 하위메뉴를 사업계획서 기준으로 정의하여 개발 범위를 명확히 한다.
- RBAC(역할 기반 접근 제어)를 통해 MES 내 데이터 접근 권한을 체계적으로 관리한다.
- 감사 로그(Audit Log)를 통해 시스템 사용 이력을 추적하여 문제 발생 시 원인 규명을 지원한다.
- 알림 기준 및 시스템 환경 설정을 관리자가 직접 제어할 수 있도록 한다.

### 범위

| 항목 | 포함 여부 |
|------|-----------|
| 4개 하위메뉴 UI/UX 요구사항 정의 | 포함 |
| RBAC 역할 정의 및 권한 매핑 | 포함 |
| API 엔드포인트 목록 정의 | 포함 |
| 외부 IdP(LDAP, SSO) 연동 | 제외 (차후 이터레이션) |
| 알림 발송 채널(SMS, 이메일) 외부 연동 | 제외 (차후 이터레이션) |

## 2. 역할(Role) 정의

MES 운영에 필요한 역할과 주요 접근 권한을 사전 정의한다.

| 역할 코드 | 역할명 | 주요 접근 권한 |
|----------|--------|--------------|
| `ROLE_ADMIN` | 시스템 관리자 | 전체 메뉴 접근, 사용자/시스템 설정, 감사 로그 열람 |
| `ROLE_FACTORY_MGR` | 공장장 | KPI 목표값 설정, 전 공정 조회, AI 의사결정 지원 |
| `ROLE_PRODUCTION_MGR` | 생산 관리자 | 공정관리, KPI 조회, AI 분석 |
| `ROLE_QUALITY_MGR` | 품질 관리자 | 검사출하관리, 품질 KPI 조회 |
| `ROLE_OPERATOR` | 공정 담당자 | 담당 공정 데이터 입력 및 조회 |
| `ROLE_VIEWER` | 조회 전용 | 읽기 전용 접근 |

## 3. 하위메뉴별 사용자 스토리

### 3-1. 사용자 관리 (`/admin/users`)

**역할**: 시스템 관리자

> "나는 시스템 관리자로서, MES 사용자의 계정을 생성/수정/삭제하고 각 사용자에게 적절한 역할을 부여하여 메뉴 및 데이터 접근 권한을 제어하고 싶다."

**수용 기준**
- 사용자 목록이 역할, 상태(활성/비활성) 필터와 함께 표시된다.
- 사용자 계정 생성(Create), 수정(Update), 비활성화(Soft Delete) 기능이 제공된다.
- 각 사용자에게 역할(Role)을 1개 이상 부여할 수 있다.
- 역할 변경 이력(변경 전/후, 변경자, 일시)이 감사 로그에 자동 기록된다.
- 비밀번호 초기화 기능이 제공된다.
- 마지막 로그인 일시가 표시된다.

---

### 3-2. 로그 관리 (`/admin/logs`)

**역할**: 시스템 관리자

> "나는 시스템 관리자로서, 누가 언제 어떤 작업을 수행했는지 감사 로그를 조회하여 문제 발생 시 원인을 추적하고 싶다."

**수용 기준**
- 시스템 전체 감사 로그(사용자 로그인/로그아웃, 데이터 생성/수정/삭제 등)가 목록으로 표시된다.
- 사용자별, 작업 유형별, 날짜 범위별 필터링이 가능하다.
- 각 로그 항목에는 사용자명, 작업 유형, 대상 리소스, IP 주소, 작업 일시가 포함된다.
- 로그는 수정/삭제가 불가하며 조회만 가능하다(불변성 보장).
- 로그 데이터는 CSV 형식으로 내보내기 할 수 있다.
- 감사 로그는 최소 1년 이상 보존된다.

---

### 3-3. 알림 설정 (`/admin/notifications`)

**역할**: 시스템 관리자, 공장장

> "나는 시스템 관리자로서, 어떤 이벤트(불량률 초과, 설비 이상 등)가 발생했을 때 누구에게 알림을 발송할지 기준과 수신 대상을 설정하고 싶다."

**수용 기준**
- 알림 규칙(이벤트 유형, 임계값, 수신 대상)을 생성/수정/삭제할 수 있다.
- 이벤트 유형별(품질 이상, 설비 이상, KPI 목표 초과, AI 추천 알림 등)로 분류하여 설정한다.
- 수신 대상은 역할(Role) 단위 또는 개별 사용자 단위로 지정할 수 있다.
- 각 사용자는 수신 채널(시스템 내 알림, 이메일) 중 선택할 수 있다.
- 알림 규칙 활성화/비활성화를 개별적으로 제어할 수 있다.
- 알림 발송 이력(발송 일시, 수신자, 이벤트 내용)이 기록된다.

---

### 3-4. 시스템 설정 (`/admin/settings`)

**역할**: 시스템 관리자

> "나는 시스템 관리자로서, MES 운영에 필요한 시스템 환경 설정(데이터 보존 기간, 언어, 시간대, API 연동 설정 등)을 관리하고 싶다."

**수용 기준**
- 시스템 전반 설정값(언어, 시간대, 데이터 보존 기간, 세션 만료 시간 등)을 조회하고 수정할 수 있다.
- 외부 시스템 인터페이스 설정(API 엔드포인트, 연결 상태)을 관리할 수 있다.
- 설정 변경 시 변경 내용과 변경자가 감사 로그에 자동 기록된다.
- 각 설정 항목에 기본값(Default)이 정의되어 있으며 초기화 기능이 제공된다.
- 운영 중 변경 시 재시작 없이 적용 가능한 항목과 재시작이 필요한 항목이 명확히 구분된다.

## 4. 기능 요구사항

### Must Have

| ID | 하위메뉴 | 요구사항 |
|----|---------|---------|
| FR-01 | 사용자 관리 | 사용자 계정 CRUD(생성/조회/수정/비활성화)가 가능해야 한다. |
| FR-02 | 사용자 관리 | RBAC 기반 역할 부여 및 변경 기능이 제공되어야 한다. |
| FR-03 | 사용자 관리 | 역할 변경 이력이 감사 로그에 자동 기록되어야 한다. |
| FR-04 | 사용자 관리 | 사용자 삭제는 Soft Delete(비활성화)로 처리되어야 한다(데이터 보존). |
| FR-05 | 로그 관리 | 사용자 로그인/로그아웃, 데이터 CRUD 감사 로그가 자동 기록되어야 한다. |
| FR-06 | 로그 관리 | 로그 수정/삭제가 불가하여야 한다(불변성 보장). |
| FR-07 | 로그 관리 | 사용자별, 작업 유형별, 날짜 범위별 필터링이 지원되어야 한다. |
| FR-08 | 알림 설정 | 이벤트 유형별 알림 규칙 CRUD가 가능해야 한다. |
| FR-09 | 알림 설정 | 수신 대상을 역할 단위 또는 개별 사용자 단위로 지정할 수 있어야 한다. |
| FR-10 | 시스템 설정 | 시스템 환경 설정값 조회 및 수정이 가능해야 한다. |
| FR-11 | 시스템 설정 | 설정 변경 이력이 감사 로그에 자동 기록되어야 한다. |

## 5. API 엔드포인트 목록

### 사용자 관리

| 메서드 | 경로 | 설명 | 권한 |
|--------|------|------|------|
| GET | `/api/admin/users` | 사용자 목록 조회 | 시스템 관리자 |
| POST | `/api/admin/users` | 사용자 계정 생성 | 시스템 관리자 |
| GET | `/api/admin/users/{id}` | 사용자 상세 조회 | 시스템 관리자 |
| PUT | `/api/admin/users/{id}` | 사용자 정보 수정 | 시스템 관리자 |
| PATCH | `/api/admin/users/{id}/deactivate` | 사용자 비활성화 (Soft Delete) | 시스템 관리자 |
| POST | `/api/admin/users/{id}/reset-password` | 비밀번호 초기화 | 시스템 관리자 |
| GET | `/api/admin/roles` | 역할 목록 조회 | 시스템 관리자 |

### 로그 관리

| 메서드 | 경로 | 설명 | 권한 |
|--------|------|------|------|
| GET | `/api/admin/audit-logs` | 감사 로그 목록 조회 | 시스템 관리자 |
| GET | `/api/admin/audit-logs?user_id={id}&action={type}&from={date}&to={date}` | 감사 로그 필터 조회 | 시스템 관리자 |
| GET | `/api/admin/audit-logs/export` | 감사 로그 CSV 내보내기 | 시스템 관리자 |

### 알림 설정

| 메서드 | 경로 | 설명 | 권한 |
|--------|------|------|------|
| GET | `/api/admin/notification-rules` | 알림 규칙 목록 조회 | 시스템 관리자 |
| POST | `/api/admin/notification-rules` | 알림 규칙 생성 | 시스템 관리자 |
| PUT | `/api/admin/notification-rules/{id}` | 알림 규칙 수정 | 시스템 관리자 |
| DELETE | `/api/admin/notification-rules/{id}` | 알림 규칙 삭제 | 시스템 관리자 |
| PATCH | `/api/admin/notification-rules/{id}/toggle` | 알림 규칙 활성화/비활성화 | 시스템 관리자 |
| GET | `/api/admin/notification-history` | 알림 발송 이력 조회 | 시스템 관리자 |

### 시스템 설정

| 메서드 | 경로 | 설명 | 권한 |
|--------|------|------|------|
| GET | `/api/admin/settings` | 시스템 설정 전체 조회 | 시스템 관리자 |
| PUT | `/api/admin/settings` | 시스템 설정 일괄 수정 | 시스템 관리자 |
| PATCH | `/api/admin/settings/{key}` | 개별 설정값 수정 | 시스템 관리자 |
| POST | `/api/admin/settings/reset` | 설정값 기본값 초기화 | 시스템 관리자 |

**기존 연관 테이블**: `users`, `roles`, `audit_logs`, `notifications`

**신규 테이블 (설계 시 고려)**
- `notification_rules` — 알림 규칙 정의 및 수신 대상 매핑
- `notification_history` — 알림 발송 이력
- `system_settings` — 시스템 환경 설정 키-값 저장소

## 6. 구현 우선순위

| 순서 | 하위메뉴 | 우선순위 | 근거 |
|------|---------|---------|------|
| 1 | 사용자 관리 | Must | RBAC이 전체 시스템 권한 제어의 기반 — 최우선 구현 |
| 2 | 로그 관리 | Must | 감사 추적은 보안/컴플라이언스 요구사항이며 사용자 관리와 동시 활성화 필요 |
| 3 | 알림 설정 | Should | AI Agent 알림 추천 기능과 연계, 조기 구현 시 타 모듈 활용 가능 |
| 4 | 시스템 설정 | Should | 운영 안정화 후 필요에 따라 점진적으로 항목 추가 |
