## 1. 개요

### 배경

TaeWoong AI-MES 프론트엔드(`apps/web/components/layout/Sidebar.tsx`)의 현재 사이드바 메뉴 구조가 사업계획서 p.40에 정의된 10대 최상위 메뉴와 다수 불일치한다. 구체적으로 메뉴 명칭 오류, 사업계획서에 없는 독립 메뉴 존재, 사업계획서에 명시된 메뉴 누락의 세 가지 유형의 Gap이 확인되었다.

### 목적

- 사업계획서 기준 메뉴 체계를 단일 진실 공급원(Single Source of Truth)으로 삼아 사이드바를 정렬한다.
- 기존 구현 기능(LOT 관리, 품질검사)을 소실 없이 적절한 계층 위치로 이동한다.
- 메뉴 명칭 표준화를 통해 사용자·이해관계자 간 언어 혼란을 제거한다.

### 범위

| 항목 | 포함 여부 |
|------|-----------|
| `Sidebar.tsx` 메뉴 레이블·라우트 변경 | 포함 |
| 신규 메뉴 페이지 스캐폴딩(기준정보관리, 데이터관리) | 포함 (플레이스홀더 수준) |
| 하위 메뉴 이동(LOT 관리, 품질검사) | 포함 |
| 기존 페이지 내부 로직·컴포넌트 변경 | 제외 |
| URL 리다이렉트 설정 | 포함 (기존 경로 보존) |

## 3. 변경 사항 상세

### 3-1. 명칭 변경 (기존 기능 유지, UI 레이블만 변경)

총 6개 메뉴의 표시 레이블을 사업계획서 표준 명칭으로 수정한다. 라우트 경로는 변경하지 않는다.

| 변경 전 | 변경 후 | 라우트 |
|---------|---------|--------|
| 대시보드 | AI 대시보드 | `/dashboard` (유지) |
| 가열공정 | 가열공정관리 | `/heating` (유지) |
| 단조/열처리 | 공정관리 | `/processes` (유지) |
| 검사출하 | 검사출하관리 | `/shipments` (유지) |
| AI Agent | AI Agent 관리 | `/ai-agent` (유지) |
| KPI 분석 | KPI 관리 | `/kpi` (유지) |
| 시스템 관리 | 사용자/시스템관리 | `/admin` (유지) |

> 구현 난이도: 낮음. `Sidebar.tsx` 내 label 문자열만 수정.

### 3-2. 신규 메뉴 추가

사업계획서에 명시되어 있으나 현재 미구현인 2개 메뉴를 추가한다.
이번 이터레이션에서는 플레이스홀더 페이지(준비 중 안내 화면)로 스캐폴딩하며, 상세 기능은 후속 Plan에서 별도 정의한다.

| 메뉴명 | 라우트 | 아이콘 제안 | 우선순위 |
|--------|--------|-------------|---------|
| 기준정보관리 | `/master-data` | `Database` | Must |
| 데이터관리 | `/data-management` | `BarChart2` | Must |

**라우트 선정 근거**
- `/master-data`: MES 업계 표준 용어 "Master Data"에 대응
- `/data-management`: 데이터 수집·이력·백업 관리의 범용 경로

### 3-3. 재배치 결정 (LOT 관리, 품질검사)

#### LOT 관리 (`/lots`)

**문제**: 사업계획서에서 LOT는 입고배합관리 및 가열공정관리 내 추적 기능으로 정의되며, 독립 최상위 메뉴가 아니다.

**결정**: 입고배합관리 하위 메뉴로 이동

**근거**
- LOT는 원자재 입고 시 생성되어 공정 전반을 흐르는 객체이므로 입고배합관리가 논리적 진입점이다.
- 기존 `/lots` 라우트와 구현 코드는 그대로 유지하고, 사이드바에서 독립 항목을 제거한 후 "입고배합관리" 항목 하위에 "LOT 조회" 서브메뉴로 등록한다.
- 기존 직접 접근 경로(`/lots`)는 Next.js redirect로 보존하여 북마크·딥링크 단절을 방지한다.

```
입고배합관리 (/raw-materials)
  └─ LOT 조회 (/lots)          ← 기존 구현 재활용
```

#### 품질검사 (`/quality`)

**문제**: 사업계획서에서 품질검사는 검사출하관리의 하위 프로세스로 정의된다.

**결정**: 검사출하관리 하위 메뉴로 이동

**근거**
- 검사 → 출하의 순차 흐름상 품질검사는 검사출하관리 내에 위치하는 것이 업무 맥락에 부합한다.
- 기존 `/quality` 라우트와 구현 코드는 유지하고, 사이드바에서 독립 항목을 제거한 후 "검사출하관리" 하위에 "품질검사" 서브메뉴로 등록한다.
- 기존 직접 접근 경로(`/quality`)는 redirect로 보존한다.

```
검사출하관리 (/shipments)
  └─ 품질검사 (/quality)       ← 기존 구현 재활용
```

## 5. 마이그레이션 전략 (기존 URL 보존)

기존 사용자 북마크, 외부 링크, 테스트 코드의 하드코딩 경로 단절을 최소화하기 위해 아래 redirect 규칙을 `next.config.js`에 추가한다.

| 기존 경로 | 신규 정착 경로 | 처리 방식 |
|-----------|---------------|----------|
| `/lots` | `/lots` (유지) | 서브메뉴로 이동 후에도 경로 자체는 유지되므로 redirect 불필요 |
| `/quality` | `/quality` (유지) | 동일 — 경로 유지, 사이드바 위치만 변경 |

> 이번 재구조화는 라우트 경로를 변경하지 않으므로 별도 redirect 설정은 불필요하다. URL은 기존과 동일하게 유지되며, 변경되는 것은 사이드바에서의 메뉴 계층 위치와 레이블뿐이다.

**향후 라우트 정규화 시 권고 패턴**

만약 후속 작업에서 라우트 경로까지 변경하게 될 경우, `next.config.js`의 `redirects()` 함수를 사용하여 영구 리다이렉트(308)로 처리한다.

```js
// next.config.js (예시 - 이번 범위 외)
async redirects() {
  return [
    { source: '/old-path', destination: '/new-path', permanent: true },
  ]
}
```

## 6. 구현 범위

### 대상 파일

| 파일 | 변경 내용 |
|------|----------|
| `apps/web/components/layout/Sidebar.tsx` | 메뉴 레이블 수정, 서브메뉴 추가, 신규 메뉴 항목 추가 |
| `apps/web/app/master-data/page.tsx` | 신규 생성 (플레이스홀더) |
| `apps/web/app/data-management/page.tsx` | 신규 생성 (플레이스홀더) |

### 구현 순서 (권장)

1. `Sidebar.tsx` — 기존 메뉴 레이블 6개 수정 (명칭 변경)
2. `Sidebar.tsx` — 신규 메뉴 2개 항목 추가 (기준정보관리, 데이터관리)
3. `Sidebar.tsx` — LOT 관리를 입고배합관리 서브메뉴로 재배치
4. `Sidebar.tsx` — 품질검사를 검사출하관리 서브메뉴로 재배치
5. 플레이스홀더 페이지 2개 신규 생성

### 완료 기준 (Acceptance Criteria)

- [ ] 사이드바 최상위 메뉴가 사업계획서 10대 메뉴와 순서·명칭 일치
- [ ] 기준정보관리, 데이터관리 메뉴 클릭 시 플레이스홀더 페이지 표시
- [ ] 입고배합관리 하위에 "LOT 조회" 서브메뉴 표시 및 `/lots` 이동 정상 동작
- [ ] 검사출하관리 하위에 "품질검사" 서브메뉴 표시 및 `/quality` 이동 정상 동작
- [ ] 기존 `/lots`, `/quality` 직접 접근 시 정상 페이지 표시 (경로 유지)
- [ ] 사이드바 독립 항목에서 "LOT 관리", "품질검사"가 제거됨
