## 1. 프로젝트 개요

### 1.1 배경 및 목적

㈜태웅은 중공업 단조·열처리 전문 제조업체로, 핵심 생산 공정(입고 → 가열 → 단조 → 열처리 → 검사 → 출하)에서 발생하는 방대한 공정 데이터를 체계적으로 관리하고 AI 기반 의사결정 지원 체계를 구축하고자 한다. 본 기획서는 MES 시스템의 공정관리·데이터관리·AI Agent·KPI·사용자관리·기준정보 6개 모듈에 대한 기능 요구사항과 구현 방향을 정의한다.

### 1.2 핵심 식별자

| 식별자 | 설명 | 적용 범위 |
|--------|------|-----------|
| Heat No. | 용해로 단위 고유 번호 | 가열 ~ 단조 ~ 열처리 전 공정 추적 |
| LOT 번호 | 출하 단위 묶음 번호 | 검사 ~ 출하 ~ 고객사 납품 추적 |

### 1.3 핵심 공정 흐름

```
[입고] → [가열] → [단조] → [열처리] → [검사] → [출하]
  |         |        |         |          |        |
Heat No. 부여    단조실적     열처리이력    검사성적서   출하LOT
```

## 2. 모듈 5 - 공정관리

### 2.1 기능 개요

**Why**: 단조·열처리 공정은 온도·압력·시간 등 수십 개 공정 파라미터가 품질에 직접 영향을 미친다. 공정 실적을 체계적으로 기록·분석하지 않으면 불량 원인 추적이 불가능하고, 작업자별 편차로 품질 산포가 발생한다.

**What**: Heat No. 기준으로 전 공정의 실적·조건·이력을 통합 관리하고, 이상 공정을 실시간 감지하며, 데이터 기반 공정 개선 방향을 도출하는 기능 모음.

### 2.2 사용자 스토리

**US-PM-001**: 공정 담당자로서, 금일 단조 공정의 생산 실적(계획 대비 달성률, Heat No. 목록)을 한 화면에서 확인하고 싶다. 그래야 교대 인수인계 시 즉시 현황 파악이 가능하기 때문이다.

**US-PM-002**: 품질 담당자로서, 특정 Heat No.의 가열-단조-열처리 전 공정 이력을 시계열로 조회하고 싶다. 고객 클레임 발생 시 공정 원인을 30분 내에 추적하기 위해서이다.

**US-PM-003**: 생산 관리자로서, 공정별 작업 조건(온도 범위, 압하량, 유지 시간)의 표준값과 실측값 편차를 자동으로 알림받고 싶다. 작업자 교체 시에도 품질 수준을 일정하게 유지하기 위해서이다.

**US-PM-004**: 공정 엔지니어로서, 최근 3개월 단조 공정 데이터를 바탕으로 불량률과 공정 파라미터 간의 상관관계를 분석하고 싶다. 공정 개선 포인트를 데이터로 입증하기 위해서이다.

**US-PM-005**: 설비 담당자로서, 현재 가동 중인 단조 프레스의 센서 데이터(압력, 온도, 스트로크)를 실시간 모니터링하고 이상 발생 시 즉시 인지하고 싶다.

### 2.3 화면 구성

#### 2.3.1 공정실적관리 화면
- **상단 필터**: 조회 기간, 공정 구분(가열/단조/열처리/검사), Heat No. 검색
- **실적 요약 카드**: 계획 수량, 실적 수량, 달성률(%), 전일 대비 증감
- **실적 테이블**: Heat No. | 강종 | 작업 시작/종료 | 중량(kg) | 작업자 | 결과 | 비고
- **목표 대비 실적 차트**: 일별/주별/월별 Bar Chart (계획 vs 실적 병렬 표시)
- **공정 개선 제안 패널**: AI 분석 결과 기반 개선 방향 (Module 9 연동)

#### 2.3.2 공정데이터모니터링 화면
- **실시간 대시보드**: 공정별 현재 파라미터 게이지 (정상/경고/이상 색상 구분)
- **트렌드 차트**: 최근 2시간 센서 데이터 Line Chart (설정값 상/하한 표시)
- **알림 패널**: 최근 이상 발생 이력, 확인 여부 상태
- **설비 현황 맵**: 공장 평면도 기반 설비별 상태 표시

#### 2.3.3 작업조건관리 화면
- **공정/강종 선택**: 드롭다운 필터로 작업 조건 기준값 조회
- **표준 조건 테이블**: 파라미터 | 표준값 | 허용 범위(±) | 단위 | 최종 수정일
- **조건 편집**: 인라인 편집 후 승인 워크플로우(등록 → 검토 → 승인)
- **이력 조회**: 조건 변경 이력 타임라인

#### 2.3.4 공정이력조회 화면
- **Heat No. 검색**: 바코드 스캔 또는 직접 입력
- **공정 흐름도**: 입고 → 가열 → 단조 → 열처리 → 검사 → 출하 단계별 실적 표시
- **단계별 상세 데이터 패널**: 클릭 시 해당 공정 상세 파라미터 팝업
- **품질-공정 연계 분석**: 검사 결과와 각 공정 파라미터 매핑 뷰

#### 2.3.5 공정데이터분석 화면
- **분석 유형 선택**: 품질 분석 / 생산성 분석 / 설비 효율 분석
- **변수 선택기**: X축/Y축 파라미터 드롭다운 (상관관계 분석용)
- **분석 결과 차트**: 산점도, 박스플롯, 히스토그램, 파레토 차트
- **AI 인사이트**: 분석 결과 기반 자동 코멘트 (Module 9 연동)
- **보고서 출력**: PDF/Excel 다운로드

### 2.4 비즈니스 로직

#### 2.4.1 공정 이상 감지 기준

```
이상 판정 기준:
- Level 1 (경고): 파라미터 > 표준값 ± 1σ
- Level 2 (주의): 파라미터 > 표준값 ± 2σ
- Level 3 (긴급): 파라미터 > 표준값 ± 3σ 또는 설비 정지

알림 발송:
- Level 1: 화면 알림
- Level 2: 화면 알림 + 담당자 앱 푸시
- Level 3: 화면 알림 + 전체 관련자 SMS/앱 푸시
```

#### 2.4.2 가열 공정 특이사항

```
재가열 발생 조건:
- 가열 후 단조 대기 시간 초과 (강종별 기준값 적용)
- 온도 하한 미달 감지 시
- 재가열 발생 시 Heat No.에 재가열 플래그(R) 자동 부여
```

#### 2.4.3 공정 실적 집계 로직

```
일일 실적 집계:
- 집계 기준: 작업 완료 시각 기준 (교대 시간 고려)
- 중량 단위: kg (소수점 1자리)
- 달성률 = (실적 중량 / 계획 중량) × 100
- 교대별 분리 집계 (주간/야간/조기)
```

### 2.5 데이터 입출력 정의

**입력 데이터**
| 항목 | 소스 | 형식 | 주기 |
|------|------|------|------|
| 공정 센서 데이터 | IoT 게이트웨이 | JSON/MQTT | 1초~30초 |
| 작업 실적 | 작업자 수동 입력 / 바코드 | Form | 작업 완료 시 |
| 계획 데이터 | 생산계획 모듈 | DB 연동 | 일 1회 |
| 품질 검사 결과 | 품질관리 모듈 | DB 연동 | 검사 완료 시 |

**출력 데이터**
| 항목 | 목적 | 형식 |
|------|------|------|
| 공정 이력 레코드 | Heat No. 추적, 품질 분석 | DB 저장 |
| 이상 알림 이벤트 | 알림 모듈 전달 | Event Queue |
| 분석 보고서 | 공정 개선 의사결정 | PDF/Excel |
| AI 학습 데이터 | Module 8/9 연동 | 정형 데이터셋 |

### 2.6 수용 기준

**AC-PM-001**: Heat No. 입력 후 3초 이내에 해당 Heat의 전 공정 이력(가열~출하)이 화면에 표시되어야 한다.

**AC-PM-002**: 공정 파라미터가 표준값 ± 3σ를 초과하는 경우, 30초 이내에 등록된 담당자에게 알림이 전송되어야 한다.

**AC-PM-003**: 작업 조건 변경은 반드시 승인 워크플로우(등록 → 검토 → 승인)를 거쳐야 하며, 미승인 조건은 운영 시스템에 반영되지 않아야 한다.

**AC-PM-004**: 공정 실적 집계 결과와 수동 계산 결과의 오차는 0.1% 미만이어야 한다.

**AC-PM-005**: 실시간 모니터링 화면의 데이터 갱신 주기는 최대 30초를 초과하지 않아야 한다.

**AC-PM-006**: 공정 이력 데이터는 생산 완료 후 최소 10년간 조회 가능해야 한다.

### 2.7 우선순위 (MoSCoW)

| 기능 | 우선순위 | 근거 |
|------|----------|------|
| 공정이력조회 (Heat No. 기준) | Must | 품질 추적성 법적 요구사항 |
| 공정실적관리 | Must | 일일 생산 운영 핵심 기능 |
| 공정데이터모니터링 (실시간) | Must | 설비 이상 즉시 대응 필수 |
| 작업조건관리 (표준화) | Should | 품질 산포 감소에 중요 |
| 공정데이터분석 (상관분석) | Could | AI 모듈 구축 후 강화 가능 |

## 3. 모듈 6 - 사용자/시스템관리

### 3.1 기능 개요

**Why**: MES 시스템은 생산 현장의 민감한 공정 데이터와 품질 정보를 다루므로, 역할 기반 접근 제어(RBAC)와 완전한 감사 추적이 필수이다. 특히 작업 조건 변경이나 품질 판정 기준 수정 같은 중요 행위는 반드시 추적 가능해야 한다.

**What**: 사용자 계정·권한 관리, 시스템 사용 이력 로깅, 알림 설정, 시스템 환경 설정을 통합 관리하는 기능 모음.

### 3.2 사용자 스토리

**US-USM-001**: 시스템 관리자로서, 신규 입사자에게 역할(공정담당/품질담당/조회전용)을 부여하고 접근 가능한 메뉴와 기능을 제어하고 싶다. 권한 없는 데이터 접근·변경을 방지하기 위해서이다.

**US-USM-002**: 감사 담당자로서, 특정 날짜에 어느 사용자가 어떤 데이터를 수정했는지 로그를 30초 내에 조회하고 싶다. ISO 9001 감사 대응 시 이력 증빙이 필요하기 때문이다.

**US-USM-003**: 공정 담당자로서, 내 담당 공정에서 이상이 발생했을 때 알림을 받을 채널(앱 푸시/이메일/SMS)과 알림 조건(레벨)을 직접 설정하고 싶다.

**US-USM-004**: 시스템 관리자로서, 시스템 점검 일정을 공지하고 점검 시간 동안 일반 사용자의 로그인을 제한하고 싶다.

### 3.3 화면 구성

#### 3.3.1 사용자관리 화면
- **사용자 목록**: 사번 | 이름 | 역할 | 부서 | 최종 로그인 | 상태(활성/비활성)
- **역할별 권한 매트릭스**: 메뉴 × 역할 권한 테이블 (읽기/쓰기/승인/삭제)
- **사용자 등록/편집 폼**: 기본 정보, 역할 선택, 담당 공정 지정
- **비밀번호 정책 설정**: 복잡도 규칙, 만료 주기, 잠금 임계값

#### 3.3.2 로그관리 화면
- **로그 조회 필터**: 기간, 사용자, 로그 유형(로그인/데이터변경/조회/오류)
- **로그 테이블**: 타임스탬프 | 사용자 | IP | 행위 | 대상 데이터 | 결과
- **로그 상세 조회**: 변경 전/후 데이터 비교 (JSON diff 형식)
- **로그 내보내기**: CSV/Excel 다운로드

#### 3.3.3 알림설정 화면
- **개인 알림 설정**: 수신 채널 선택, 알림 레벨 임계값 설정
- **공정별 알림 그룹**: 공정 → 담당자 매핑 관리
- **알림 이력 조회**: 발송된 알림 목록, 수신 확인 여부

#### 3.3.4 시스템설정 화면
- **환경 설정**: 타임존, 언어, 데이터 갱신 주기, 세션 타임아웃
- **인터페이스 관리**: 외부 시스템(ERP, IoT 게이트웨이) 연동 상태 모니터링
- **점검 공지 관리**: 점검 일정 등록, 사용자 접속 제한 설정
- **백업 상태 조회**: 최근 백업 일시, 용량, 상태

### 3.4 비즈니스 로직

#### 3.4.1 RBAC 역할 정의

| 역할 | 읽기 | 데이터 입력 | 조건 변경 | 승인 | 시스템 설정 |
|------|------|------------|-----------|------|------------|
| 관리자 | 전체 | 전체 | 가능 | 가능 | 가능 |
| 공정담당 | 담당 공정 | 담당 공정 | 가능(승인 필요) | 불가 | 불가 |
| 품질담당 | 전체 | 품질 데이터 | 품질 기준만 | 품질 승인 | 불가 |
| 조회전용 | 허가 범위 | 불가 | 불가 | 불가 | 불가 |

## 4. 모듈 7 - 기준정보관리

### 4.1 기능 개요

**Why**: 단조 제품은 강종(Steel Grade)별로 가열 온도, 단조 조건, 열처리 사양이 다르며, 고객사별 품질 기준도 상이하다. 이 기준 데이터가 정확하지 않으면 AI 분석 결과와 KPI 측정이 모두 무의미해진다.

**What**: 강종별·고객사별 품질 기준, 공정별 작업 표준(SOP), 시스템 운영에 필요한 코드 기준 정보를 중앙에서 관리하는 기능 모음.

### 4.2 사용자 스토리

**US-BIM-001**: 품질 담당자로서, 신규 강종 수주 시 해당 강종의 화학 성분 허용 범위, 기계적 성질 기준값을 시스템에 등록하고 싶다. 검사 자동 판정 기능이 새 강종에도 즉시 적용되도록 하기 위해서이다.

**US-BIM-002**: 공정 엔지니어로서, 단조 공정 SOP를 시스템에 등록하고, 작업자가 현장 태블릿에서 언제든지 최신 버전 SOP를 조회할 수 있게 하고 싶다. 작업 표준 미준수로 인한 불량을 방지하기 위해서이다.

**US-BIM-003**: 시스템 관리자로서, 공정 코드·설비 코드·품목 코드를 중앙에서 관리하고, 코드 변경 시 연관 모듈에 자동 반영되도록 하고 싶다. 코드 불일치로 인한 데이터 오류를 방지하기 위해서이다.

**US-BIM-004**: 영업 담당자로서, 고객사별 특수 품질 요구사항(추가 검사 항목, 강화된 기준)을 등록하고 해당 고객사 수주 건에 자동 적용되게 하고 싶다.

### 4.3 화면 구성

#### 4.3.1 품질기준관리 화면
- **강종 목록**: 강종 코드 | 강종명 | 규격(KS/ASTM/JIS) | 적용 고객사 | 버전
- **품질 기준 상세**: 화학 성분 테이블 (C, Si, Mn, P, S 등 성분별 Min/Max)
- **기계적 성질 기준**: 인장강도, 항복강도, 연신율, 충격값 (조건별 기준)
- **고객사별 특수 기준**: 표준 기준 외 추가 요구사항 레이어 관리
- **기준 이력**: 버전별 변경 이력 비교

#### 4.3.2 작업표준관리 화면
- **SOP 목록**: 공정 | SOP 번호 | 버전 | 작성일 | 승인자 | 상태
- **SOP 내용**: 단계별 작업 절차, 주의사항, 첨부 이미지/동영상
- **개정 관리**: 이전 버전 보관, 개정 이력 추적
- **현장 출력**: A4 인쇄 최적화 레이아웃

#### 4.3.3 코드관리 화면
- **코드 그룹 트리**: 품목/공정/설비/강종/검사항목 분류 트리
- **코드 테이블**: 코드 | 코드명 | 상위코드 | 사용여부 | 비고
- **코드 등록/수정**: 인라인 편집, 중복 코드 자동 검증
- **코드 사용 현황**: 각 코드가 참조되는 화면/기능 목록

### 4.4 비즈니스 로직

#### 4.4.1 기준 정보 버전 관리

```
버전 관리 규칙:
- 주요 변경(기준값 변경): 버전 번호 +1 (예: v1.0 → v2.0)
- 경미한 수정(오탈자 등): 부버전 +1 (예: v1.0 → v1.1)

품질 기준 변경 시 연동:
- 변경 승인 즉시 검사 판정 로직에 신규 기준 적용
- 변경 이전 검사 결과는 당시 기준으로 유효
```

**출력**: 검사 판정 기준 데이터 (품질모듈 제공), 공정 조건 기준값 (공정모듈 제공), 코드 참조 데이터 (전 모듈 공통)

### 4.6 수용 기준

**AC-BIM-001**: 품질 기준 변경은 반드시 승인 후 효력이 발생해야 하며, 미승인 상태에서는 검사 판정 로직에 적용되지 않아야 한다.

**AC-BIM-002**: 코드 삭제 시 해당 코드를 참조하는 데이터가 존재하면 삭제가 차단되고, 참조 위치 목록이 표시되어야 한다.

**AC-BIM-003**: 모든 기준 정보 변경 이력은 변경자, 변경 일시, 변경 전/후 값이 영구 보존되어야 한다.

**AC-BIM-004**: 강종별 품질 기준 조회 응답 시간은 2초 이내여야 한다.

**AC-BIM-005**: SOP는 PDF 형식으로 출력 가능해야 하며, 현장 A4 용지에 가독성 있게 인쇄되어야 한다.

## 5. 모듈 8 - 데이터관리

### 5.1 기능 개요

**Why**: MES에서 생성되는 IoT 센서 데이터, 공정 실적, 품질 검사 결과는 현재 각 공정별로 분산 저장되어 있어 통합 분석이 어렵다. AI 모델 학습과 KPI 산출에는 품질이 보증된 통합 데이터셋이 필요하다.

**What**: IoT·공정 데이터를 단일 저장소에 통합하고, LOT 기준 통합 조회·시각화·다운로드와 AI 학습 데이터셋 관리를 제공하는 기능 모음.

### 5.2 사용자 스토리

**US-DM-001**: 데이터 분석가로서, LOT 번호 하나를 입력했을 때 해당 LOT의 전 공정(가열~출하) 데이터와 품질 검사 결과를 하나의 통합 뷰에서 확인하고 싶다. 공정-품질 연계 분석을 위해서이다.

**US-DM-002**: AI 엔지니어로서, 불량/양품 레이블이 붙은 과거 공정 데이터를 필터링하고 결측치·이상치 처리 기준을 적용한 학습용 데이터셋을 내려받고 싶다. ML 모델 학습 효율을 높이기 위해서이다.

**US-DM-003**: 생산 관리자로서, 월별 생산량·불량률·설비가동률 트렌드를 대시보드 차트로 보고 싶다. 경영진 보고 자료를 별도로 만들지 않고 시스템에서 바로 활용하기 위해서이다.

**US-DM-004**: 품질 담당자로서, 특정 강종의 최근 6개월 검사 데이터를 Excel로 다운로드하고 싶다. 자체 통계 분석 도구에서 추가 분석을 수행하기 위해서이다.

### 5.3 화면 구성

#### 5.3.1 데이터통합관리 화면
- **데이터 소스 현황**: IoT 게이트웨이 연결 상태, 마지막 수신 시각, 데이터 수신 건수
- **통합 파이프라인 모니터링**: ETL 처리 현황, 오류 건수, 처리 지연 경고
- **데이터 정합성 지표**: 소스별 누락 데이터율, 이상값 비율 대시보드
- **수동 데이터 업로드**: CSV/Excel 업로드 (검증 후 통합 저장소 반영)

#### 5.3.2 데이터조회 화면
- **검색 조건**: LOT 번호 / Heat No. / 기간 / 공정 / 강종 복합 검색
- **통합 뷰 테이블**: 공정-품질-출하 연계 데이터 통합 표시
- **컬럼 선택기**: 표시할 데이터 항목 사용자 정의
- **연계 분석 링크**: 품질 검사 결과 상세, 공정 이력 상세 바로가기

#### 5.3.3 데이터시각화 화면
- **대시보드 빌더**: 드래그앤드롭으로 차트 배치
- **차트 유형**: Line (트렌드), Bar (비교), Scatter (상관관계), Heatmap (패턴)
- **기간 슬라이더**: 실시간 ~ 과거 데이터 범위 조정
- **대시보드 저장/공유**: 개인 대시보드 저장, URL 공유

#### 5.3.4 데이터다운로드 화면
- **다운로드 조건**: 데이터 유형, 기간, 필터 조건 설정
- **형식 선택**: Excel (.xlsx), CSV (.csv)
- **다운로드 이력**: 요청자, 요청 시각, 데이터 범위, 파일명 기록
- **대용량 처리**: 100,000건 초과 시 백그라운드 처리 후 이메일 알림

#### 5.3.5 AI학습데이터관리 화면
- **데이터셋 목록**: 데이터셋명 | 목적 | 레코드 수 | 결측률 | 생성일 | 버전
- **데이터 품질 리포트**: 결측률, 이상치 비율, 클래스 불균형 지표
- **전처리 설정**: 결측치 처리 방법, 이상치 처리 기준, 정규화 설정
- **데이터셋 버전 관리**: 학습에 사용된 데이터셋 버전 고정 및 재현 가능성 보장

### 5.4 비즈니스 로직

#### 5.4.1 데이터 통합 파이프라인

```
데이터 수집 → 유효성 검증 → 표준화 → 통합 저장소 적재

유효성 검증 규칙:
- 범위 검증: 센서값이 물리적 허용 범위 내에 있는지 확인
- 타임스탬프 검증: 미래 시각 데이터 거부, 24시간 초과 지연 데이터 플래그
- 중복 제거: Heat No. + 공정 코드 + 타임스탬프 조합 유니크 보장
- 필수 항목 검증: Heat No., 공정 코드, 타임스탬프 누락 시 거부

표준화:
- 온도: °C 통일
- 중량: kg 통일 (소수점 1자리)
- 시각: UTC+9 (KST) 통일
```

#### 5.4.2 AI 학습 데이터 품질 기준

```
데이터셋 품질 요구사항:
- 결측률: 항목별 결측률 < 5% (초과 시 데이터셋 품질 경고 표시)
- 이상치 처리:
  * IQR 방법: Q1 - 1.5×IQR ~ Q3 + 1.5×IQR 범위 밖 → 이상치 플래그
  * 처리 옵션: 제거 / 평균대체 / 중앙값대체 / 경계값으로 캡핑
- 클래스 불균형: 불량/양품 비율이 1:10 초과 시 오버샘플링 권장 알림
- 최소 데이터 수: 학습 데이터 5,000건 이상, 검증 데이터 1,000건 이상
- 레이블 검증: 검사 합격/불합격 레이블 100% 기입 필수

데이터셋 버전 관리:
- 학습 사용 데이터셋은 불변(Immutable) 처리
- 데이터셋 ID + 버전으로 모델-데이터 연계 추적
```

#### 5.4.3 데이터 보존 및 아카이빙

```
티어 구분:
- Hot (최근 1년): 실시간 조회 가능, SSD 저장
- Warm (1~2년): 조회 가능, 응답 시간 5초 이내 허용
- Cold (2년 이상): 아카이빙, 조회 시 복원 요청 필요 (24시간 이내 처리)

삭제 정책:
- 센서 데이터: 2년 후 Cold 이전, 5년 후 삭제
- 공정 실적: 10년 보존 후 삭제
- AI 학습 데이터셋: 해당 모델 폐기 후 1년 보존
```

### 5.5 데이터 입출력 정의

**입력**: IoT 게이트웨이 스트리밍 데이터, 각 모듈 DB 데이터, 수동 업로드 파일
**출력**: 통합 조회 결과셋, 시각화 차트 데이터, 다운로드 파일, AI 학습 데이터셋

### 5.6 수용 기준

**AC-DM-001**: LOT 번호 기준 통합 조회 시 해당 LOT의 전 공정 데이터가 5초 이내에 반환되어야 한다 (데이터 건수 10,000건 이하 기준).

**AC-DM-002**: AI 학습 데이터셋 생성 시 결측률이 5%를 초과하는 항목은 자동으로 품질 경고가 표시되고, 담당자 승인 없이는 학습용으로 배포되지 않아야 한다.

**AC-DM-003**: 데이터 다운로드 이력은 100% 기록되어야 하며, 다운로드한 데이터의 범위(기간, 건수)가 포함되어야 한다.

**AC-DM-004**: IoT 데이터 수집 오류율이 0.1%를 초과하는 경우 데이터 관리자에게 자동 알림이 발송되어야 한다.

**AC-DM-005**: 데이터 통합 파이프라인의 처리 지연이 설정 임계값(기본 5분)을 초과하면 모니터링 화면에 경고 표시가 나타나야 한다.

## 6. 모듈 9 - AI Agent 통합관리

### 6.1 기능 개요

**Why**: 현장 작업자와 관리자는 복잡한 데이터베이스 구조를 알지 못해도 원하는 정보를 즉시 얻을 수 있어야 한다. 자연어로 질문하면 AI가 관련 데이터를 조회·분석·해석해서 실행 가능한 인사이트를 제공하는 것이 목표이다.

**What**: 자연어 기반 전 공정 정보 통합 조회, AI 자동 분석, 의사결정 추천, 이상 알림 및 조건 추천, 질문 이력 관리를 제공하는 기능 모음.

### 6.2 사용자 스토리

**US-AI-001**: 생산 관리자로서, "이번 주 단조 공정 불량률이 높은 원인이 뭐야?"라고 자연어로 물으면 AI가 관련 공정 데이터를 분석해서 원인과 개선 방향을 알려주기를 원한다.

**US-AI-002**: 공정 담당자로서, "Heat No. H2024-0512 의 공정 이력을 요약해줘"라고 요청하면 해당 Heat의 전 공정 요약 정보를 표 형식으로 즉시 받고 싶다.

**US-AI-003**: 설비 담당자로서, 공정 파라미터 이상이 감지되면 AI가 자동으로 "단조 프레스 1호기 온도 이상 (현재: 1,280°C, 기준: 1,150~1,250°C) - 예상 원인: 냉각 시스템 점검 필요"와 같은 구체적 알림을 받고 싶다.

**US-AI-004**: 품질 담당자로서, "최근 3개월 중 불량률이 가장 높았던 강종과 해당 시점의 공정 조건을 알려줘"라고 질문하면 AI가 데이터를 분석해서 답변해 주기를 원한다.

**US-AI-005**: 생산 관리자로서, AI와의 질의응답 이력을 나중에 다시 조회하고, 유사한 질문 패턴을 통해 AI가 더 정확한 답변을 제공하도록 개선되기를 원한다.

### 6.3 화면 구성

#### 6.3.1 통합AI질의 화면 (Chat Interface)
- **채팅 UI**: 메시지 버블 형식, 사용자 질문 / AI 응답 구분 표시
- **빠른 질문 버튼**: 자주 묻는 질문 템플릿 버튼 (예: "오늘 생산 현황", "이번 주 불량 현황")
- **컨텍스트 선택**: 질문 범위 선택 (전체 / 공정별 / 기간별)
- **응답 내 데이터 링크**: AI 응답에 참조된 데이터로 바로가기 링크 포함
- **피드백 버튼**: 응답 유용성 평가 (좋음/보통/나쁨)

#### 6.3.2 생산/품질분석 화면
- **분석 트리거**: 자동 분석 스케줄 (일별/주별) 또는 수동 실행
- **분석 결과 카드**: 핵심 지표 요약, 이상 징후, 개선 권고사항
- **근거 데이터 뷰**: AI 분석의 근거가 된 데이터 테이블 표시
- **분석 이력**: 과거 분석 결과 조회 및 비교

#### 6.3.3 의사결정지원 화면
- **추천 정보 패널**: 현재 공정 상태 기반 조건 추천 (예: "현재 강종 기준 최적 가열 온도: 1,180°C")
- **시나리오 분석**: 공정 조건 변경 시 예상 품질 변화 시뮬레이션
- **추천 근거**: 추천 도출 근거 데이터 및 유사 과거 사례 표시

#### 6.3.4 알림및추천 화면
- **AI 알림 피드**: 이상 감지 알림, 개선 조건 추천, 예방 정비 알림
- **알림 상세**: 이상 내용, 예상 원인, 권고 조치, 관련 데이터 링크
- **조치 결과 입력**: 알림에 대한 실제 조치 내용 입력 (AI 학습 피드백)

#### 6.3.5 사용자질문이력 화면
- **질문 목록**: 질문 일시 | 질문자 | 질문 내용 | 응답 요약 | 피드백 평가
- **검색 및 필터**: 키워드, 기간, 사용자, 평가 점수 필터
- **질문 재실행**: 과거 질문 클릭 시 동일 질문 재실행

### 6.4 비즈니스 로직

#### 6.4.1 AI Agent 자연어 처리 흐름

```
[1단계: 질의 입력]
사용자 자연어 입력 → 텍스트 전처리 (특수문자 제거, 정규화)

[2단계: 의도 파악 (NLU - Natural Language Understanding)]
- 의도 분류: 조회(Query) / 분석(Analysis) / 추천(Recommendation) / 알림(Alert)
- 개체 추출 (NER):
  * 공정명: 가열, 단조, 열처리, 검사
  * 식별자: Heat No., LOT 번호
  * 기간: 오늘, 이번 주, YYYY-MM-DD
  * 지표: 불량률, 생산량, 가동률, OEE
- 모호한 경우: 명확화 질문 자동 생성

[3단계: 데이터 조회 계획 수립]
- 필요한 데이터 소스 식별 (공정 DB / 품질 DB / 설비 DB)
- 조회 쿼리 자동 생성 (Text-to-SQL)
- 조회 권한 검증 (RBAC 적용)

[4단계: 데이터 조회 및 분석]
- 데이터 조회 실행
- 통계 분석 (평균, 표준편차, 트렌드, 상관관계)
- 이상 패턴 감지

[5단계: 응답 생성]
- 자연어 요약 생성 (결과 + 인사이트)
- 관련 차트/테이블 자동 생성
- 근거 데이터 링크 포함
- 다음 조치 추천 포함

[6단계: 피드백 수집 및 학습]
- 사용자 평가 수집 (좋음/보통/나쁨)
- 낮은 평가 응답은 재학습 큐에 등록
- 질문-응답 이력 저장
```

#### 6.4.2 자연어 질의 예시 케이스

**케이스 1: 공정 이력 조회**
```
질문: "Heat No. H2024-0512 공정 이력 보여줘"
NLU 분류: 조회(Query), 개체: Heat No.=H2024-0512
조회: 해당 Heat의 가열/단조/열처리/검사 이력 전체
응답 형식: 공정별 단계 요약 테이블 + 각 공정 상세 링크
```

**케이스 2: 불량 원인 분석**
```
질문: "이번 주 단조 공정 불량률이 왜 높아?"
NLU 분류: 분석(Analysis), 개체: 공정=단조, 기간=이번 주
조회: 이번 주 단조 불량 건수, 불량 유형, 해당 시점 공정 파라미터
분석: 불량 유형별 파레토, 파라미터 이상과 불량의 상관관계
응답 형식: 불량 원인 순위 + 개선 권고사항
```

**케이스 3: 최적 조건 추천**
```
질문: "SM45C 강종 단조 시 최적 가열 온도 알려줘"
NLU 분류: 추천(Recommendation), 개체: 강종=SM45C, 공정=단조
조회: SM45C 과거 가열 온도 데이터 + 해당 품질 결과
분석: 품질 합격률이 높은 가열 온도 구간 도출
응답 형식: 최적 온도 범위 + 근거(과거 N건 데이터 기반)
```

**케이스 4: KPI 현황 조회**
```
질문: "이번 달 OEE가 얼마야?"
NLU 분류: 조회(Query), 개체: 지표=OEE, 기간=이번 달
조회: 당월 가동시간, 성능률, 품질률 데이터
계산: OEE = 가용성 × 성능률 × 품질률
응답 형식: OEE 수치 + 전월 대비 증감 + 하위 지표 분해
```

**케이스 5: 재가열 발생 분석**
```
질문: "최근 1개월 재가열 발생 현황과 원인 분석해줘"
NLU 분류: 분석(Analysis), 개체: 지표=재가열률, 기간=최근 1개월
조회: 재가열 발생 건수, 발생 시각, 대기 시간, 작업자 정보
분석: 재가열 주요 원인 (대기 시간 초과 비율, 온도 이탈 비율)
응답 형식: 재가열률 추이 차트 + 원인 분석 + 예방 권고
```

**케이스 6: 설비 이상 예측**
```
질문: "단조 프레스 1호기 다음 주 정비가 필요할까?"
NLU 분류: 추천(Recommendation), 개체: 설비=단조프레스1호기
조회: 최근 진동, 온도, 압력 센서 트렌드 + 정비 이력
분석: 이상 징후 패턴 감지, 예상 고장 확률 산출
응답 형식: 정비 필요 여부 + 근거 센서 데이터 + 권고 조치
```

**케이스 7: 납기 준수 분석**
```
질문: "A고객사 납기 준수율 현황 알려줘"
NLU 분류: 조회(Query), 개체: 고객사=A, 지표=납기준수율
조회: A사 수주 건별 계획 납기일 vs 실제 출하일
계산: 납기 준수율 = 납기 내 출하 건수 / 전체 수주 건수 × 100
응답 형식: 납기 준수율 수치 + 지연 건 목록 + 평균 지연 일수
```

**AC-AI-004**: 공정 이상 감지 알림은 이상 발생 후 1분 이내에 AI 알림 피드에 표시되어야 한다.

**AC-AI-005**: 모든 질의 이력은 사용자 개인 및 관리자 레벨에서 조회 가능해야 하며, 3년간 보존되어야 한다.

**AC-AI-006**: RBAC 권한이 없는 데이터에 대한 AI 질의는 "접근 권한 없음" 응답을 반환해야 하며, 해당 데이터가 노출되지 않아야 한다.

## 7. 모듈 10 - KPI관리

### 7.1 기능 개요

**Why**: 경영진과 현장 관리자는 생산성·품질·납기 성과를 수치로 파악해야 의사결정과 개선 활동이 가능하다. 현재는 KPI 데이터를 수동으로 집계하여 보고하므로 시간이 오래 걸리고 오류가 발생한다.

**What**: 태웅 단조업체에 특화된 KPI(OEE, 납기 준수율, 불량률, 재가열률, 검사 합격률)를 자동 산출·시각화하고, 목표값 대비 달성률을 관리하며, AI 기반 개선 인사이트를 제공하는 기능 모음.

### 7.2 사용자 스토리

**US-KPI-001**: 생산 관리자로서, 매일 아침 단조 프레스별 OEE를 대시보드에서 즉시 확인하고 싶다. 설비 효율이 낮은 원인을 조기에 파악하고 당일 조치하기 위해서이다.

**US-KPI-002**: 품질 담당자로서, 공정별·강종별 불량률을 주간/월간 단위로 트렌드 차트로 확인하고 싶다. 불량 증가 추세를 조기에 발견하고 예방 조치를 취하기 위해서이다.

**US-KPI-003**: 경영진으로서, 월간 KPI 달성률(생산성/품질/납기)을 한 페이지 요약 리포트로 받고 싶다. 경영 회의에서 빠르게 현황을 공유하기 위해서이다.

**US-KPI-004**: 생산 기술팀으로서, KPI 목표값을 분기별로 업데이트하고, 목표 달성 여부에 따라 알림을 받고 싶다. 목표 수준을 지속 상향 조정하기 위해서이다.

### 7.3 화면 구성

#### 7.3.1 생산성KPI조회 화면
- **KPI 카드**: 생산량(금일/주간/월간), 설비가동률(%), 공정 리드타임(시간)
- **OEE 분해 차트**: 가용성 × 성능률 × 품질률 구성 요소 Stacked Bar
- **설비별 OEE 비교**: 단조 프레스 호기별 OEE 비교 Bar Chart
- **리드타임 분포**: 공정별 리드타임 히스토그램

#### 7.3.2 품질KPI조회 화면
- **불량률 트렌드**: 공정별·강종별 일/주/월 불량률 Line Chart
- **불량 유형 파레토**: 불량 원인 상위 항목 파레토 차트
- **출하 품질 합격률**: 월별 합격률 추이 + 고객사별 비교
- **클레임 발생률**: 클레임 건수/출하 건수, 클레임 원인 분류
- **검사 합격률**: 공정별·강종별 합격률 히트맵

#### 7.3.3 KPI관리 화면
- **KPI 목표값 설정**: KPI 항목별 기간(월/분기/연간) 목표값 입력
- **달성률 현황**: 목표 vs 실적 게이지 차트, 달성률(%) 표시
- **KPI 기준 이력**: 목표값 변경 이력 (변경자, 변경일, 변경 이유)
- **AI 개선 인사이트**: KPI 미달성 항목에 대한 AI 원인 분석 및 개선 방향
- **KPI 리포트 생성**: PDF/PowerPoint 형식 경영 보고용 리포트 자동 생성

### 7.4 비즈니스 로직

#### 7.4.1 태웅 단조 특화 KPI 공식

**1. 설비가동률 (Machine Availability Rate)**
```
설비가동률(%) = (가동시간 / 계획가동시간) × 100

- 가동시간 = 계획가동시간 - 비계획정지시간 (고장, 셋업, 조정)
- 계획가동시간 = 총 근무시간 - 계획정지시간 (정기PM, 식사 시간)
- 목표 기준값: ≥ 85%
```

**2. OEE (Overall Equipment Effectiveness)**
```
OEE(%) = 가용성(%) × 성능률(%) × 품질률(%)

- 가용성(%) = 가동시간 / 계획가동시간 × 100
- 성능률(%) = (실제 생산량 × 이상 사이클 타임) / 가동시간 × 100
- 품질률(%) = 양품 수량 / 전체 생산 수량 × 100
- 세계적 수준: OEE ≥ 85% (태웅 1차 목표: OEE ≥ 75%)
```

**3. 납기 준수율 (On-Time Delivery Rate)**
```
납기준수율(%) = (납기 내 출하 건수 / 전체 수주 건수) × 100

- 납기 준수 기준: 고객 요청 납기일 당일 또는 이전 출하
- 조기 납품(납기일 3일 이전): 별도 플래그 표시
- 목표 기준값: ≥ 95%
```

**4. 공정 불량률 (Process Defect Rate)**
```
공정불량률(%) = (불량 중량 / 전체 생산 중량) × 100
또는
공정불량률(건수%) = (불량 건수 / 전체 생산 건수) × 100

- 공정별 개별 불량률 산출 (가열/단조/열처리/검사 구분)
- 강종별 불량률 추가 집계
- 목표 기준값: ≤ 3% (공정별 상이)
```

**5. 재가열률 (Re-Heating Rate)**
```
재가열률(%) = (재가열 발생 건수 / 전체 가열 건수) × 100

- 재가열 정의: 단조 작업 불가로 재차 가열로에 투입한 건
- 월별/작업자별 집계
- 목표 기준값: ≤ 2%
```

**6. 검사 합격률 (Inspection Pass Rate)**
```
검사합격률(%) = (검사 합격 건수 / 전체 검사 건수) × 100

- 공정 중간 검사 합격률과 최종 검사 합격률 구분
- 강종별·고객사별 합격률 세분화
- 목표 기준값: ≥ 97%
```

**7. 클레임 발생률 (Customer Claim Rate)**
```
클레임발생률(%) = (클레임 발생 건수 / 출하 건수) × 100

- 클레임 유형 분류: 치수 불량, 재질 불량, 표면 불량, 납기 지연
- 클레임 금액 기준 집계 병행
- 목표 기준값: ≤ 0.5%
```

#### 7.4.2 KPI 집계 주기

```
실시간 집계 (1시간 주기 갱신):
- 설비가동률, 현재 가동/정지 상태

일별 집계 (익일 00:30 자동 실행):
- 생산량, 불량률, 재가열률, 검사 합격률

주별 집계 (매주 월요일 01:00):
- 주간 OEE, 납기 준수율 업데이트

월별 집계 (매월 1일 02:00):
- 전월 전체 KPI 확정, 목표 대비 달성률 산출
```

#### 7.4.3 KPI 목표 달성 알림

```
달성률 알림 기준:
- 목표 대비 80% 미만: 경고 알림 (담당자)
- 목표 대비 70% 미만: 긴급 알림 (담당자 + 관리자)
- 목표 초과 달성: 달성 축하 알림 (선택적)

AI 개선 인사이트 자동 생성:
- KPI 미달 항목에 대해 연관 공정 데이터 분석
- 상위 3가지 개선 방향 자동 제시
- 과거 유사 사례와 개선 효과 데이터 제공
```

### 7.5 데이터 입출력 정의

**입력**: 공정 실적 데이터, 설비 가동 상태 데이터, 검사 결과 데이터, 출하 정보, KPI 목표값 (사용자 입력)
**출력**: KPI 산출값, 달성률, 트렌드 차트, 경영 보고 리포트, AI 개선 인사이트

### 7.6 수용 기준

**AC-KPI-001**: OEE 산출 결과와 수동 계산 결과의 오차가 0.1% 미만이어야 하며, 계산 근거 데이터(가동시간, 성능률, 품질률)가 상세 조회 가능해야 한다.

**AC-KPI-002**: KPI 대시보드는 최대 3초 이내에 로딩 완료되어야 한다 (월간 집계 데이터 기준).

**AC-KPI-003**: KPI 목표값 변경 시 변경 이력(변경자, 일시, 변경 전/후 값, 사유)이 자동 기록되어야 한다.

**AC-KPI-004**: KPI 달성률이 목표 대비 80% 미만으로 떨어지면 해당 담당자에게 자동 알림이 발송되어야 한다.

**AC-KPI-005**: 경영 보고용 KPI 리포트는 PDF 형식으로 자동 생성되어야 하며, 전월 대비 비교 데이터가 포함되어야 한다.

**AC-KPI-006**: 재가열률, 검사 합격률은 강종별 세분화 조회가 가능해야 한다.

### 7.7 우선순위 (MoSCoW)

| 기능 | 우선순위 | 근거 |
|------|----------|------|
| 생산성KPI조회 (OEE, 가동률) | Must | 설비 효율 관리 핵심 지표 |
| 품질KPI조회 (불량률, 합격률) | Must | 품질 관리 핵심 지표 |
| KPI 목표값 설정 및 달성률 | Must | 목표 관리 없이는 KPI 의미 없음 |
| AI 개선 인사이트 | Should | AI 모듈 완성 후 연동 가능 |
| 경영 보고용 리포트 자동 생성 | Should | 보고 업무 효율화 |
| KPI 시나리오 예측 | Won't | 현 단계 스코프 외, 2차 개발 검토 |

## 9. 모듈 간 의존성 및 통합 아키텍처

```
[기준정보관리 - M7]
     ↓ 품질 기준, 코드 데이터 제공
[공정관리 - M5] ←→ [데이터관리 - M8]
     ↓ 공정 이벤트          ↓ 통합 데이터
[사용자/시스템관리 - M6]    [AI Agent - M9]
     ↓ 권한, 알림 설정       ↓ 분석 결과, 알림
                        [KPI관리 - M10]
```

**핵심 데이터 흐름**:
1. M7(기준정보) → M5(공정관리): 작업 조건 기준값, 품질 판정 기준
2. M5(공정관리) → M8(데이터관리): 공정 실적, 센서 데이터 적재
3. M8(데이터관리) → M9(AI Agent): 분석용 통합 데이터셋 제공
4. M8(데이터관리) → M10(KPI관리): KPI 산출 원본 데이터 제공
5. M9(AI Agent) → M10(KPI관리): 개선 인사이트 연동
6. M6(사용자관리) → 전 모듈: RBAC 권한 제어, 감사 로그 수집
