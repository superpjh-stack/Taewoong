## 1. 프로젝트 개요

### 1.1 배경

㈜태웅은 중공업 단조·열처리 전문 제조업체로, 핵심 생산 공정은 다음과 같다.

```
입고 → 가열(가열로) → 단조 → 열처리 → 검사 → 출하
```

가열 공정은 단조 품질을 결정하는 최상위 인과 공정이다. 가열 온도 편차 또는 체류시간 이탈은 단조 크랙, 표면 스케일 과다, 내부 조직 불균일로 이어지며, 이는 후공정(열처리·검사)에서 불합격 → 재작업 → 납기 지연 → 클레임의 연쇄 손실을 유발한다.

검사·출하 공정은 고객사 납기와 품질 신뢰를 결정하는 최종 관문이다. 수작업 기반의 합부 판정 및 출하 스케줄 관리는 판단 오류와 데이터 누락 위험을 내포한다.

### 1.2 목표

- 가열로 실시간 모니터링으로 과열·미열 즉시 감지 및 경보
- ML 기반 최적 온도·체류시간 예측으로 재가열 발생률 30% 이상 감소
- 검사 데이터 + 공정 데이터 통합으로 출하 합부 판정 자동화
- Heat No. 기반 완전한 Traceability 확보 (입고 → 출하 전 구간)
- AI Agent를 통한 납기 리스크 선행 감지 및 클레임 대응 자동화

### 1.3 핵심 식별자

| 식별자 | 정의 | 활용 범위 |
|--------|------|-----------|
| Heat No. | 제강 배치(Batch) 단위 식별자 | 입고 ~ 출하 전 공정 추적 |
| LOT 번호 | 생산 로트 단위 식별자 | 단조 ~ 출하 품질 관리 |

## 2. 모듈 3: 가열공정관리

### 2.1 가열공정 데이터 모니터링

#### 2.1.1 기능 개요 (Why/What)

**Why**: 가열로 내 존별 온도 편차는 실시간으로 파악되지 않으면 소재 불량이 발생한 후에야 인지된다. 과열은 산화 스케일 증가와 결정립 조대화를 유발하고, 미열은 단조 하중 증가와 표면 크랙을 유발한다. 현장 작업자가 수동으로 계기판을 확인하는 방식은 다점(多點) 가열로 환경에서 사각지대를 만든다.

**What**: 가열로 존별 설정온도 vs 실측온도를 실시간 시각화하고, 이탈 발생 시 즉시 경보를 발령하는 모니터링 대시보드. 승온 곡선, 체류시간, 에너지 사용량을 통합 표시한다.

#### 2.1.2 가열로 구역(존) 정의

| 존 번호 | 존 명칭 | 역할 | 온도 범위 (강종 기준) |
|---------|---------|------|----------------------|
| Zone 1 | 예열존 (Preheating Zone) | 상온 소재의 급격한 열충격 방지, 표면-코어 온도 균등화 | 400 ~ 700°C |
| Zone 2 | 가열존 1 (Heating Zone 1) | 목표 온도까지 1차 승온 | 700 ~ 1,050°C |
| Zone 3 | 가열존 2 (Heating Zone 2) | 목표 온도까지 2차 승온, 코어 온도 추종 | 1,050 ~ 1,250°C |
| Zone 4 | 균열존 (Soaking Zone) | 소재 전단면 온도 균일화, 최종 단조 온도 유지 | 1,100 ~ 1,280°C |

> 고합금강(예: Cr-Mo계, Ni-Cr-Mo계)은 예열존에서 저속 승온(≤80°C/hr)이 필수이며, 균열존 체류시간을 일반강 대비 1.5배 이상 확보해야 한다.

#### 2.1.3 사용자 스토리

1. **나는 가열로 운전원으로서**, 각 존의 실시간 온도를 한 화면에서 확인하기 위해, 존별 설정온도·실측온도·편차를 색상 코드(정상/경고/위험)로 표시하는 대시보드를 원한다.
2. **나는 품질 관리자로서**, 과열·미열 이벤트 발생 시 즉각 조치하기 위해, 온도 이탈 감지 후 5초 이내에 알람(화면 팝업 + SMS/카카오 알림)이 발령되는 기능을 원한다.
3. **나는 생산 관리자로서**, 가열로별 에너지 효율을 월간 비교하기 위해, 단위 소재 중량당 에너지 소비량(kWh/ton) 트렌드 차트를 원한다.
4. **나는 공정 엔지니어로서**, 특정 소재의 승온 패턴이 기준치와 얼마나 다른지 파악하기 위해, 실제 승온곡선과 강종별 표준 승온곡선을 오버레이(overlay) 비교하는 기능을 원한다.

#### 2.1.4 화면 구성

**메인 영역**
- 상단: 가열로 평면도 레이아웃 (Zone 1~4 배치, 현재 소재 위치 표시)
- 중단 좌: 존별 실시간 온도 게이지 (설정값·실측값·편차 수치 표시)
- 중단 우: 현재 소재의 실시간 승온 곡선 (시간 vs 온도, Line Chart)
- 하단 좌: 에너지 사용량 바 차트 (시간별/일별 전환)
- 하단 우: 알람 이력 테이블

**차트/그래프 타입**
- 존별 온도: Gauge Chart + 색상 배경 (초록/노랑/빨강)
- 승온 곡선: Multi-line Chart (실측 + 표준 오버레이)
- 에너지 사용량: Stacked Bar Chart (존별 구분)
- 체류시간 진행률: Horizontal Progress Bar

**필터/검색 조건**
- 가열로 번호 선택 (멀티 선택 가능)
- 조회 기간 (오늘 / 최근 7일 / 최근 30일 / 사용자 지정)
- 강종 코드 필터
- 알람 등급 필터 (경고/위험/전체)

**알람 이력 테이블 컬럼**
| 컬럼명 | 설명 |
|--------|------|
| 발생일시 | 알람 발생 타임스탬프 |
| 가열로 번호 | 해당 가열로 ID |
| 존 번호 | 이탈 발생 존 |
| Heat No. | 해당 소재 식별자 |
| 알람 유형 | 과열/미열/온도편차/체류이탈 |
| 설정값 (°C) | 기준 온도 |
| 실측값 (°C) | 실제 측정 온도 |
| 편차 (°C) | 설정 - 실측 차이 |
| 대응 여부 | 조치 완료/미완료 |
| 조치 내용 | 작업자 입력 메모 |

**실시간 갱신 주기**: 온도 데이터 5초, 에너지 데이터 1분, 알람 즉시 push

#### 2.1.5 비즈니스 로직

**온도 이탈 판정 기준**
```
경고(Warning): |실측온도 - 설정온도| > ±15°C 이고 ±30°C 이하
위험(Critical): |실측온도 - 설정온도| > ±30°C
과열(Overheat): 실측온도 > 강종별 최고 허용온도
미열(Underheat): 균열존 실측온도 < 목표 단조온도 - 50°C
```

**체류시간 계산**
```
체류시간 = 소재 추출 타임스탬프 - 소재 장입 타임스탬프
기준 체류시간 = F(강종, 소재직경_mm, 중량_ton) × 보정계수
보정계수 = 초기소재온도 < 100°C 이면 1.2, 그 외 1.0
최소 체류시간 위반 시 → 자동 경보 + 추출 잠금 요청
```

**에너지 효율 지표**
```
단위 에너지 소비 = 총 가스 사용량(Mcal) / 가열 소재 총 중량(ton)
목표: ≤ 150 Mcal/ton (공장 기준값, 강종별 별도 기준 적용)
```

#### 2.1.6 데이터 입출력

| 구분 | 항목 | 소스/대상 |
|------|------|-----------|
| 입력 | 존별 실측온도 (4개 채널/존) | PLC/SCADA OPC-UA |
| 입력 | 가스 유량계 데이터 | 에너지 계측 시스템 |
| 입력 | 소재 장입/추출 이벤트 | 바코드/RFID 스캔 |
| 입력 | 강종별 설정온도 레시피 | 작업조건관리 DB |
| 출력 | 알람 이벤트 | 알람 관리 서비스 → SMS/카카오 |
| 출력 | 가열 이력 레코드 | MES DB (공정이력조회 활용) |
| 출력 | 에너지 KPI | KPI 대시보드 |

#### 2.1.7 수용 기준 (Acceptance Criteria)

1. **AC-MON-01**: 존별 실측온도가 PLC로부터 수신 후 5초 이내에 화면에 반영되어야 한다.
2. **AC-MON-02**: 온도 이탈(위험 등급) 발생 시 10초 이내에 화면 알람 팝업과 담당자 SMS 발송이 완료되어야 한다.
3. **AC-MON-03**: 표준 승온곡선과 실제 승온곡선의 오버레이 차트에서 시간축·온도축이 동기화되어 동일 척도로 표시되어야 한다.
4. **AC-MON-04**: 에너지 사용량은 kWh(전기) 및 Mcal(가스) 단위로 모두 표시되며 단위 전환 버튼을 제공해야 한다.
5. **AC-MON-05**: 알람 이력은 최소 12개월 데이터를 검색 가능해야 하며, Excel 내보내기를 지원해야 한다.

#### 2.1.8 우선순위 (MoSCoW)

| 항목 | 우선순위 | 근거 |
|------|---------|------|
| 존별 실시간 온도 모니터링 | Must | 핵심 안전/품질 기능 |
| 온도 이탈 알람 | Must | 즉각 대응 필수 |
| 승온 곡선 오버레이 | Should | 품질 분석 핵심이나 초기 운영 가능 |
| 에너지 사용량 트렌드 | Should | 비용 절감 가시화 |
| 가열로 평면도 레이아웃 | Could | 직관성 향상, UI 개발 비용 높음 |

### 2.2 작업조건관리

#### 2.2.1 기능 개요 (Why/What)

**Why**: 강종·제품 규격별 가열 조건(온도 프로파일, 체류시간)은 수십 ~ 수백 가지에 달하며, 이를 작업자 개인 경험이나 종이 기준서에 의존하면 조건 오입력·누락이 발생한다. 조건 변경 시 이력이 남지 않으면 품질 이슈 발생 시 원인 추적이 불가능하다.

**What**: 강종·규격별 표준 가열 레시피를 등록·조회·수정하고, 모든 변경 이력을 보존하는 마스터 데이터 관리 기능.

#### 2.2.2 사용자 스토리

1. **나는 공정 엔지니어로서**, 신규 강종 수주 시 즉시 기준 레시피를 등록하기 위해, 강종 코드·규격·목표온도·존별 설정온도·체류시간을 입력하고 저장하는 레시피 등록 폼을 원한다.
2. **나는 품질 관리자로서**, 품질 이슈 발생 시 당시 적용된 가열 조건을 확인하기 위해, 특정 날짜·Heat No. 기준으로 사용된 레시피와 변경 이력을 조회하는 기능을 원한다.
3. **나는 생산 관리자로서**, 동일 강종에서 레시피 변경 전후의 품질 성과를 비교하기 위해, 레시피 버전별 단조 불량률 통계를 조회하는 기능을 원한다.
4. **나는 현장 반장으로서**, 승인되지 않은 레시피가 실수로 적용되는 것을 방지하기 위해, 레시피 등록·수정 시 엔지니어 → 관리자 2단계 승인 워크플로우를 원한다.

#### 2.2.3 화면 구성

**메인 영역**
- 좌: 레시피 목록 테이블 (강종코드/규격/버전/상태 기준 필터)
- 우: 선택된 레시피 상세 조회 패널
  - 존별 설정온도 입력 필드 (4개 존)
  - 승온 속도(°C/hr) 입력
  - 균열 체류시간(min) 입력
  - 적용 강종·규격 범위
  - 변경 이력 타임라인

**필터/검색 조건**
- 강종 코드 (자동완성)
- 제품 규격 (직경·중량 범위)
- 레시피 상태 (활성/비활성/승인대기)
- 최종 수정일 범위

**레시피 목록 테이블 컬럼**
| 컬럼명 | 설명 |
|--------|------|
| 레시피 ID | 고유 식별자 |
| 강종 코드 | 소재 강종 분류 |
| 제품 규격 | 직경(mm) × 길이(mm) 범위 |
| 목표 단조온도 (°C) | 균열존 출구 기준 |
| 버전 | 개정 이력 번호 |
| 상태 | 활성/비활성/승인대기 |
| 최종 수정자 | 수정 작업자 ID |
| 최종 수정일 | 타임스탬프 |
| 승인자 | 승인 관리자 ID |

#### 2.2.4 비즈니스 로직

**레시피 버전 관리**
```
신규 등록 → v1.0 (Draft)
수정 요청 → v1.1 (Draft) : 기존 v1.0은 보존
엔지니어 제출 → v1.1 (Pending Approval)
관리자 승인 → v1.1 (Active), v1.0 → Archived
관리자 반려 → v1.1 (Rejected), 사유 기록
```

**강종별 승온 패턴 기준**
| 강종 분류 | 예열존 승온 속도 | 비고 |
|-----------|----------------|------|
| 탄소강 (C ≤ 0.45%) | ≤ 150°C/hr | 일반 조건 |
| 합금강 (Cr-Mo계) | ≤ 100°C/hr | 수소 취화 위험 |
| 고합금강 (Ni-Cr-Mo계) | ≤ 80°C/hr | 열충격 민감 |
| 스테인리스강 | ≤ 120°C/hr | 열팽창 제어 필요 |

**체류시간 기준 공식**
```
기준 체류시간(min) = 소재직경(mm) × 강종계수 / 60
강종계수 = 탄소강: 1.0, 합금강: 1.3, 고합금강: 1.5
예: Cr-Mo강 Φ400mm → 400 × 1.3 / 60 ≒ 8.7분/mm → 총 약 87분 (직경 100mm 기준)
```

#### 2.2.5 데이터 입출력

| 구분 | 항목 | 소스/대상 |
|------|------|-----------|
| 입력 | 레시피 파라미터 | 엔지니어 수동 입력 |
| 입력 | 강종 마스터 | ERP 연동 |
| 출력 | 활성 레시피 | 가열로 제어 시스템 (OPC-UA 전송) |
| 출력 | 변경 이력 | 감사 로그 DB |
| 출력 | 레시피 적용 기록 | 공정이력 DB |

#### 2.2.6 수용 기준

1. **AC-RCP-01**: 레시피 저장 시 동일 강종·규격·온도 범위의 활성 레시피가 존재하면 중복 등록 경고를 표시하고 사용자 확인을 요구해야 한다.
2. **AC-RCP-02**: 승인 워크플로우에서 승인 대기 상태의 레시피는 가열로에 자동 적용되지 않아야 한다.
3. **AC-RCP-03**: 모든 레시피 변경 이력(수정자, 수정일시, 변경 전/후 값)은 삭제 불가능한 감사 로그로 보존되어야 한다.
4. **AC-RCP-04**: 특정 레시피를 적용하여 생산된 Heat No. 목록 조회가 1초 이내에 응답해야 한다.

### 2.3 공정이력조회

#### 2.3.1 기능 개요 (Why/What)

**Why**: 품질 불량 발생 시 "어떤 조건으로 가열되었는가"를 빠르게 역추적해야 한다. 또한 가열-단조-열처리 간 온도 연계 분석은 공정 최적화의 핵심 데이터이나, 현재는 각 공정별 데이터가 분산되어 있어 통합 분석이 불가능하다.

**What**: Heat No. 기준으로 가열 온도 이력, 승온 곡선, 체류시간, 이후 단조·열처리 품질 결과를 하나의 뷰에서 연결하여 조회하는 공정 Traceability 기능.

#### 2.3.2 사용자 스토리

1. **나는 품질 엔지니어로서**, 클레임이 발생한 제품의 가열 조건을 즉시 확인하기 위해, Heat No. 입력 후 3초 이내에 해당 소재의 전체 가열 이력(온도 프로파일·체류시간·작업자·레시피 버전)이 조회되는 기능을 원한다.
2. **나는 공정 개선 담당자로서**, 가열 조건과 단조 불량률의 상관관계를 분석하기 위해, 가열온도 편차와 이후 단조·열처리 결과를 하나의 리포트로 연결하는 분석 뷰를 원한다.
3. **나는 고객사 감사 대응 담당자로서**, 납품한 제품의 생산 이력을 고객에게 제출하기 위해, Heat No. 기준 가열 이력 전체를 PDF/Excel로 출력하는 기능을 원한다.

#### 2.3.3 화면 구성

#### 2.3.4 비즈니스 로직

**공정 간 품질 영향 분석 지표**
```
가열 편차 지수 = (전체 체류시간 중 온도 이탈 시간) / 전체 체류시간 × 100 (%)

### 2.4 공정데이터분석

#### 2.4.1 기능 개요 (Why/What)

**Why**: 반복적인 재가열은 에너지 낭비(1회 재가열 시 추가 에너지 약 50~80Mcal/ton)이자 소재 산화에 의한 품질 저하를 수반한다. 재가열 원인을 데이터로 분석하지 않으면 근본 원인 제거가 불가능하다.

**What**: 가열 온도, 에너지 소비, 체류시간을 기반으로 공정 효율을 정량 분석하고, 재가열 이벤트의 원인을 분류·시각화하는 분석 기능.

#### 2.4.2 사용자 스토리

1. **나는 공정 엔지니어로서**, 재가열 발생 원인 Top 5를 매월 파악하기 위해, 재가열 이벤트를 원인 유형별(온도이탈·체류시간부족·설비결함·작업대기 등)로 분류한 파이 차트와 트렌드 차트를 원한다.
2. **나는 생산 관리자로서**, 가열로별 에너지 효율 격차를 파악하기 위해, 가열로 번호별 단위 에너지 소비량(Mcal/ton) 비교 차트를 원한다.
3. **나는 원가 담당자로서**, 재가열로 인한 월간 추가 비용을 정량화하기 위해, 재가열 건수 × 평균 추가 에너지 × 에너지 단가를 자동 계산하는 월간 원가 영향 리포트를 원한다.

#### 2.4.3 화면 구성

**메인 영역**
- 상단 KPI 카드: 분석 기간 내 재가열 건수, 재가열률(%), 평균 에너지 효율, 목표 대비 달성률
- 중단: 재가열 원인 분류 Pie Chart + 월별 재가열 건수 Bar Chart
- 하단 좌: 가열로별 에너지 효율 비교 Bar Chart
- 하단 우: 체류시간 준수율 Heat Map (강종 × 기간)

**필터/검색 조건**
- 분석 기간 (월/분기/연도)
- 가열로 번호
- 강종 분류
- 재가열 원인 유형

#### 2.4.4 비즈니스 로직

**재가열 원인 분류 코드**
| 코드 | 원인 | 정의 |
|------|------|------|
| R01 | 온도 미달 | 균열존 실측온도 < 목표온도 - 50°C |
| R02 | 체류시간 부족 | 실제 체류시간 < 기준 체류시간 × 0.9 |
| R03 | 설비 결함 | 버너 불량, 열전대 오류 등 설비 이상 코드 연계 |
| R04 | 작업 대기 | 단조 설비 비가동으로 소재 냉각 후 재장입 |
| R05 | 계획 변경 | 생산 계획 변경으로 소재 회수 후 재가열 |

**재가열 원가 영향 계산**
```
재가열 추가 원가(월) = 재가열 건수 × 평균 추가 에너지(Mcal/ton) × 평균 소재 중량(ton) × 에너지 단가(원/Mcal)
재가열률(%) = 재가열 건수 / 전체 가열 건수 × 100
목표 재가열률: ≤ 3% (프로젝트 목표)
```

#### 2.4.5 수용 기준

1. **AC-ANA-01**: 분석 기간 내 재가열 이벤트 전체가 원인 코드별로 자동 분류되어야 하며, 미분류(Unknown) 비율은 10% 이하를 유지해야 한다.
2. **AC-ANA-02**: 월간 재가열 원가 영향 계산 시 에너지 단가를 관리자가 설정·변경 가능해야 한다.
3. **AC-ANA-03**: 모든 분석 차트는 PNG/SVG 이미지 및 원본 데이터 Excel 형식으로 내보낼 수 있어야 한다.

#### 2.4.6 우선순위 (MoSCoW)

| 항목 | 우선순위 |
|------|---------|
| 재가열 원인 분류 및 통계 | Must |
| 가열로별 에너지 효율 비교 | Should |
| 재가열 원가 영향 계산 | Should |
| 체류시간 준수율 Heat Map | Could |

### 2.5 가열 최적화 AI 분석

#### 2.5.1 기능 개요 (Why/What)

**Why**: 작업자 경험에 의존하는 가열 조건 설정은 최적값에서 벗어나는 경향이 있다. ML 모델은 과거 수천 건의 가열-단조-품질 데이터로부터 최적 온도·체류시간을 학습하여 작업자에게 제안함으로써 품질 변동을 줄이고 에너지를 절감한다.

**What**: ML 기반으로 최적 가열온도·체류시간을 예측하고, 과열·미열·재가열 발생 가능성을 사전에 예측하여 작업자에게 제공하는 AI 분석 기능.

#### 2.5.2 사용자 스토리

1. **나는 가열로 운전원으로서**, 다음 소재 장입 전에 최적 설정온도를 추천받기 위해, 강종·중량·규격·초기온도를 입력하면 AI가 존별 권장 설정온도와 예상 체류시간을 제시하는 기능을 원한다.
2. **나는 품질 관리자로서**, 현재 가열 진행 중인 소재의 과열·미열 리스크를 사전에 인지하기 위해, AI가 현재 승온 트렌드를 분석하여 15분 후 예상 온도와 리스크 등급을 표시하는 기능을 원한다.
3. **나는 공정 엔지니어로서**, AI 추천 조건의 신뢰도를 평가하기 위해, 각 예측에 대한 신뢰도 점수(0~100%)와 근거 데이터(유사 과거 사례 Top 3)를 함께 제공받는 기능을 원한다.

#### 2.5.3 ML 모델 입력 피처

| 피처 | 데이터 타입 | 설명 |
|------|------------|------|
| 강종 코드 | Categorical | One-hot encoding 처리 |
| 소재 중량 (ton) | Numerical | 0.5 ~ 50 ton |
| 소재 직경 (mm) | Numerical | 100 ~ 1,200 mm |
| 소재 길이 (mm) | Numerical | 500 ~ 5,000 mm |
| 초기 소재온도 (°C) | Numerical | 상온(20) ~ 600°C |
| 목표 단조온도 (°C) | Numerical | 1,050 ~ 1,280°C |
| 에너지 단가 (원/Mcal) | Numerical | 비용 최적화 가중치 |
| 가열로 번호 | Categorical | 설비별 특성 반영 |
| 계절(월) | Categorical | 외기온도 영향 보정 |
| 이전 소재 가열 잔열 여부 | Boolean | 연속 조업 시 잔열 반영 |

#### 2.5.4 ML 모델 출력

| 출력 | 설명 |
|------|------|
| 존별 권장 설정온도 (°C) | Zone 1~4 각각 |
| 권장 체류시간 (min) | 총 시간 및 존별 분배 |
| 예상 에너지 소비 (Mcal) | 권장 조건 기준 |
| 과열 발생 확률 (%) | 0~100%, 신뢰도 포함 |
| 미열 발생 확률 (%) | 0~100%, 신뢰도 포함 |
| 재가열 발생 확률 (%) | 0~100%, 신뢰도 포함 |
| 신뢰도 점수 | 0~100%, 학습 데이터 유사도 기반 |
| 근거 유사 사례 Top 3 | Heat No. + 조건 + 결과 |

#### 2.5.5 AI 신뢰도 점수 정의

```
신뢰도 점수 = (유사 학습 데이터 수 × 가중치1)
              + (입력 피처의 학습 분포 내 위치 × 가중치2)
              + (모델 앙상블 예측 일치도 × 가중치3)

등급 기준:
  HIGH   (80~100%): 추천 조건 적용 권장
  MEDIUM (60~79%):  추천 조건 참고, 작업자 판단 병행
  LOW    (0~59%):   신규 강종/규격 등 학습 데이터 부족, 수동 설정 권장

신뢰도 < 60% 시 AI 추천 조건을 가열로에 자동 전송하지 않음 (안전 장치)
```

#### 2.5.6 화면 구성

**메인 영역**
- 좌: AI 예측 입력 패널 (소재 정보 입력 폼)
- 중: AI 추천 결과 패널
  - 존별 권장 설정온도 테이블
  - 신뢰도 점수 Gauge (색상 코드: 초록/노랑/빨강)
  - 리스크 예측 (과열/미열/재가열 확률 Progress Bar)
- 우: 근거 유사 사례 패널 (Top 3 카드 형식)

**실시간 예측 패널** (가열 진행 중 소재용)
- 현재 온도 트렌드 기반 15분 후 예상 온도
- 잔여 체류시간 예측
- 실시간 리스크 등급 업데이트 (1분 주기)

#### 2.5.7 수용 기준

1. **AC-AI-01**: ML 모델의 가열온도 예측 정확도는 실제 최적온도 대비 ±20°C 이내여야 하며, 이는 월간 단위로 모델 성능 리포트를 통해 검증된다.
2. **AC-AI-02**: 모든 AI 예측 결과에 신뢰도 점수(0~100%)가 함께 표시되어야 하며, 신뢰도 60% 미만 시 시각적 경고 배지(LOW CONFIDENCE)가 표시되어야 한다.
3. **AC-AI-03**: AI 추천 조건은 작업자가 수동으로 수정 가능해야 하며, 수정 시 원본 AI 추천값과 실제 사용값이 모두 이력으로 저장되어 모델 재학습 데이터로 활용되어야 한다.
4. **AC-AI-04**: 재가열 발생 예측 확률 ≥ 70% 시 자동으로 알람이 발령되고 관련 Heat No. 정보와 함께 담당자에게 통보되어야 한다.

#### 2.5.8 우선순위 (MoSCoW)

|------|---------|
| 신규 소재 장입 전 온도·체류시간 추천 | Must |
| 신뢰도 점수 표시 | Must |

## 3. 모듈 4: 검사출하관리

### 3.1 출하관리

#### 3.1.1 기능 개요 (Why/What)

**Why**: 출하 LOT 관리와 납기 스케줄이 분리된 시스템(Excel + 수기)으로 운영되면 납기 누락, 우선순위 오류, 부분 출하 관리 실패가 발생한다. 특히 동일 제품을 여러 차례 나누어 출하하는 분할 출하 케이스는 수작업으로 추적이 어렵다.

**What**: 출하 LOT 단위의 납기 스케줄 통합 관리, 출하 진행 상태 가시화, 분할 출하 추적 기능.

#### 3.1.2 사용자 스토리

1. **나는 출하 담당자로서**, 오늘 출하해야 할 LOT 목록과 준비 상태를 한눈에 확인하기 위해, 당일 출하 예정 항목을 납기 긴급도 순서로 정렬하고 검사 완료 여부를 함께 표시하는 출하 큐(Queue) 화면을 원한다.
2. **나는 영업 담당자로서**, 고객사별 납기 달성 현황을 실시간으로 파악하기 위해, 고객사별 납기 준수율과 지연 예상 건수를 표시하는 대시보드를 원한다.
3. **나는 물류 담당자로서**, 분할 출하 진행 현황을 추적하기 위해, 주문 수량 대비 출하 완료 수량과 잔여 수량을 자동 집계하는 기능을 원한다.

#### 3.1.3 화면 구성

**메인 영역**
- 상단 KPI: 당일 출하 예정 건수, 검사 완료율(%), 납기 지연 위험 건수, 출하 완료 건수
- 중단: 출하 예정 목록 테이블 (납기 긴급도 색상 코드 적용)
- 하단: 납기 캘린더 뷰 (월별 출하 건수 히트맵)

**출하 예정 목록 테이블 컬럼**
| 컬럼명 | 설명 |
|--------|------|
| 출하 LOT 번호 | 출하 단위 식별자 |
| Heat No. | 연계 소재 배치 |
| 고객사 코드/명 | |
| 제품 사양 | 강종·규격·수량 |
| 납기일 | 고객사 요청 납기 |
| 잔여일 | 납기 - 오늘 |
| 검사 상태 | 완료/진행중/미시작 |
| 출하 상태 | 대기/부분출하/완료 |
| 납기 리스크 지수 | 0~100 (AI 산정) |
| 담당자 | |

**실시간 갱신 주기**: 검사 상태 5분, 납기 리스크 지수 30분

#### 3.1.4 비즈니스 로직

**납기 리스크 지수 계산 공식**
```
납기 리스크 지수 = W1 × 잔여납기일_역산 + W2 × 검사_미완료_비율 + W3 × 생산_진행율_역산 + W4 × 클레임_이력_가중치

여기서:
  잔여납기일_역산 = MAX(0, (기준납기일 - 오늘) ≤ 3일이면 100점, ≤ 7일이면 70점, ≤ 14일이면 40점, 초과 0점)
  검사_미완료_비율 = (미완료 검사 항목 수 / 전체 필수 검사 항목 수) × 100
  생산_진행율_역산 = (1 - 완료 공정 수 / 전체 공정 수) × 100
  클레임_이력_가중치 = 해당 고객사 최근 1년 클레임 건수 × 5 (최대 20점)

  W1=0.35, W2=0.30, W3=0.25, W4=0.10

리스크 등급:
  HIGH   (≥ 70): 즉시 조치 필요, 빨간색 표시
  MEDIUM (40~69): 주의 관찰, 노란색 표시
  LOW    (< 40):  정상, 초록색 표시
```

#### 3.1.5 수용 기준

1. **AC-SHP-01**: 출하 LOT의 납기 리스크 지수가 70 이상으로 산정될 때, 영업 담당자와 생산 관리자에게 자동 알림이 발송되어야 한다.
2. **AC-SHP-02**: 분할 출하 시 각 출하 이벤트마다 주문 잔량이 자동으로 차감되어야 하며, 잔량 0 도달 시 해당 LOT가 자동으로 '출하 완료' 상태로 전환되어야 한다.
3. **AC-SHP-03**: 납기 캘린더 뷰는 최소 3개월 미래 납기 예정을 표시하며, 캘린더 날짜 클릭 시 해당일 출하 LOT 목록이 즉시 조회되어야 한다.

#### 3.1.6 우선순위 (MoSCoW)

| 항목 | 우선순위 |
|------|---------|
| 출하 LOT 상태 관리 | Must |
| 납기 리스크 지수 산정 | Must |
| 고객사별 납기 달성 현황 | Should |
| 납기 캘린더 뷰 | Should |
| 분할 출하 자동 잔량 추적 | Must |

### 3.2 출하이력조회

#### 3.2.1 기능 개요 (Why/What)

**Why**: 고객사로부터 클레임이 접수되면 "해당 제품이 어떤 공정을 거쳐 어떤 검사를 통과했는가"를 즉시 답변할 수 있어야 한다. 이를 위해 출하 이력과 검사 결과를 Heat No. 기반으로 완전히 연결된 Traceability 체계가 필요하다.

**What**: 제품별·고객사별 출하 이력과 Heat No. 기준 검사 결과를 통합 조회하고, 클레임 대응 자료로 즉시 출력하는 기능.

#### 3.2.2 사용자 스토리

1. **나는 품질 관리자로서**, 고객사 클레임 발생 시 해당 제품의 모든 검사 이력을 5분 이내에 파악하기 위해, 고객사명·제품사양·납품일 조건으로 검색하면 Heat No. 기준 전체 검사 결과(기계적 성질·NDT·치수검사)가 조회되는 기능을 원한다.
2. **나는 영업 담당자로서**, 고객사의 정기 품질 감사에 대응하기 위해, 특정 기간·고객사 기준 납품 제품의 검사 성적서를 일괄 PDF로 출력하는 기능을 원한다.
3. **나는 출하 담당자로서**, 동일 Heat No. 소재가 여러 고객사에 분할 납품되었을 때 각각의 검사 결과를 추적하기 위해, Heat No. 기준으로 파생된 모든 LOT와 출하 이력을 계층 구조로 조회하는 기능을 원한다.

#### 3.2.3 화면 구성

  3순위: ASTM 규격
```

3. **AC-TRC-03**: 클레임 접수 건은 해당 Heat No.·LOT 번호와 자동 연결되어 검색 가능해야 하며, 처리 상태가 실시간으로 갱신되어야 한다.

### 3.3 출하데이터관리

#### 3.3.1 기능 개요 (Why/What)

**Why**: 출하 및 검사 데이터는 품질 AI 분석의 입력이자 법적·계약적 증거 자료다. 데이터 불일치(중복 입력, 누락, 수정 이력 부재)는 AI 예측 정확도 저하와 감사 리스크로 이어진다.

**What**: 출하·검사 데이터를 단일 신뢰 저장소(Single Source of Truth)로 통합 관리하고, 데이터 정합성을 자동 검증하며, AI 분석 및 KPI 산출의 기반 데이터를 제공하는 기능.

#### 3.3.2 사용자 스토리

1. **나는 데이터 관리자로서**, 검사 데이터 입력 오류를 사전에 방지하기 위해, 검사값 입력 시 강종별 허용 범위를 벗어나면 즉시 경고를 표시하고 저장을 차단하는 유효성 검증 기능을 원한다.
2. **나는 품질 팀장으로서**, 데이터 수정 이력을 감사하기 위해, 모든 검사 데이터 수정 시 수정 전/후 값, 수정자, 수정 사유를 의무 기록하는 감사 로그 기능을 원한다.
3. **나는 AI 시스템 관리자로서**, AI 모델 학습용 데이터 품질을 보장하기 위해, 결측값·이상치·중복 레코드를 자동 탐지하고 보고하는 데이터 품질 대시보드를 원한다.

#### 3.3.3 비즈니스 로직

**데이터 정합성 검증 규칙**
```
규칙 1 (범위 검증): 인장강도 입력값 < 200 MPa 또는 > 2,000 MPa → 입력 오류 경고
규칙 2 (논리 검증): 항복강도 > 인장강도 → 물리적 불가, 저장 차단
규칙 3 (중복 검증): 동일 Heat No. + 동일 검사 항목 + 동일 시험 날짜 중복 입력 시 경고
규칙 4 (필수 항목): 출하 전 필수 검사 항목(기계적 성질 전 항목 + NDT) 미완료 시 출하 승인 차단
규칙 5 (이상치 탐지): 동일 강종 과거 데이터 대비 3-sigma 초과 값 → 이상치 플래그 자동 마킹
```

**KPI 데이터 제공 구조**
```
제공 KPI:
  - 월별 최초합격률 (First Pass Yield, FPY)
  - 강종별 평균 기계적 성질 트렌드
  - NDT 등급별 발생 빈도
  - 고객사별 클레임 발생률
  - 출하 후 현장 불량률 (반품 기준)
```

#### 3.3.4 수용 기준

1. **AC-DAT-01**: 데이터 정합성 검증 규칙 1~5가 모두 실시간으로 적용되어야 하며, 규칙 위반 시 저장이 차단되거나 경고가 표시되어야 한다.
2. **AC-DAT-02**: 검사 데이터 수정 시 수정 사유 입력이 필수이며, 수정 이력은 삭제 불가능한 감사 로그로 영구 보존되어야 한다.
3. **AC-DAT-03**: 데이터 품질 대시보드는 결측값 비율·이상치 건수·중복 건수를 일간 단위로 자동 집계하여 표시해야 한다.

#### 3.3.5 우선순위 (MoSCoW)

### 3.4 출하 AI Agent

#### 3.4.1 기능 개요 (Why/What)

**Why**: 출하 합부 판정은 다수의 검사 항목을 고객사별 스펙과 대조하는 복잡한 작업으로, 숙련된 품질 담당자가 수행해도 누락·오판단 리스크가 있다. 납기 리스크 역시 다변수 요인(공정 진행률·검사 상태·물류 일정)을 동시에 고려해야 하므로 자동화 가치가 높다.

**What**: 검사 결과 + 공정 데이터를 통합 분석하여 출하 적합성을 자동 판단하고, 납기 리스크를 예측하며, 클레임 대응 및 고객 질의에 자동으로 응답하는 AI Agent.

#### 3.4.2 사용자 스토리

1. **나는 품질 관리자로서**, 출하 전 모든 검사 항목의 합부 판정을 신속하고 정확하게 완료하기 위해, AI Agent가 검사 결과와 고객사 스펙을 자동 대조하여 합격/불합격 판정 및 판정 근거를 제시하는 기능을 원한다.
2. **나는 영업 담당자로서**, 납기 지연 리스크를 사전에 고객사에 알리기 위해, AI Agent가 납기 리스크 HIGH 항목을 자동 감지하고 예상 지연 일수와 원인을 포함한 고객 통보 초안을 생성하는 기능을 원한다.
3. **나는 고객사 담당자로서(외부 포털 접근)**, 납품 예정 제품의 검사 진행 상황을 직접 확인하기 위해, AI Agent에게 자연어로 "Heat No. XXXX 검사 상태 어떻게 됩니까?"라고 질의하면 즉시 답변을 받는 기능을 원한다.
4. **나는 품질 팀장으로서**, AI Agent의 출하 판정 신뢰도를 사람이 검토하기 위해, AI 판정 결과에 신뢰도 점수와 함께 최종 승인 버튼이 있어 사람 확인 후 출하 승인이 확정되는 Human-in-the-Loop 프로세스를 원한다.

#### 3.4.3 AI Agent 기능 구성

**기능 1: 출하 적합성 자동 판단**
```
입력:
  - 전체 검사 결과 (기계적 성질 + NDT + 치수검사)
  - 해당 고객사 스펙 (마스터 DB 조회)
  - 적용 규격 (ASTM/KS)
  - 공정 이력 (가열 품질 등급 포함)

처리:
  1. 각 검사 항목별 합부 판정 (규격 대비)
  2. 고객사 맞춤 스펙 추가 조건 검토
  3. 공정 이력 이상 여부 교차 검토
  4. 종합 합부 판정 산출

출력:
  - 종합 판정: PASS / CONDITIONAL PASS / FAIL
  - 항목별 판정 상세 (합격 이유 or 불합격 이유)
  - 신뢰도 점수 (0~100%)
  - 판정 근거 요약 (자연어)
  - 조건부 합격 시 조건 명시
```

**기능 2: 납기 리스크 분석**
```
입력:
  - 납기 리스크 지수 (3.1 출하관리 산정값)
  - 현재 공정 진행 상황
  - 물류 일정 (Lead Time DB)
  - 유사 과거 납기 이행 패턴

출력:
  - 납기 달성 확률 (%)
  - 예상 지연 일수 (지연 시)
  - 지연 원인 Top 3
  - 고객사 통보 초안 (이메일 형식)
  - 만회 방안 제안 (공정 순서 조정, 외주 활용 등)
```

**기능 3: 클레임 대응**
```
입력:
  - 클레임 내용 (자연어 또는 구조화 데이터)
  - 해당 제품의 Heat No. / LOT 번호
  - 관련 공정 이력 전체
  - 유사 클레임 과거 사례 DB

출력:
  - 원인 분석 (공정 이력 기반)
  - 책임 소재 판단 (제조 vs 고객사 사용 vs 운송)
  - 클레임 처리 방향 제안
  - 재발 방지 조치 초안
  - 고객 회신 공문 초안 (한국어/영어)
```

**기능 4: 고객 질의 응답 (RAG 기반)**
```
지식 베이스:
  - 검사 결과 DB
  - 공정 이력 DB
  - 출하 스케줄 DB
  - 제품 사양 마스터

지원 질의 유형:
  - "Heat No. XXXX 검사 결과 알려줘"
  - "다음 주 납품 예정 제품 준비 상태 어떻게 돼?"
  - "이번 달 ○○사 납품 현황 요약해줘"
  - "LOT XXXX 불합격 이유가 뭐야?"

응답 형식:
  - 자연어 응답 + 관련 데이터 테이블
  - 출처 데이터 참조 명시 (투명성 확보)
```

#### 3.4.4 AI Agent 신뢰도 점수 상세 정의

```
출하 판정 신뢰도 점수 산출:

신뢰도 = BASE_SCORE × (1 - PENALTY_FACTOR)

BASE_SCORE 구성:
  - 검사 데이터 완전성: 필수 항목 모두 입력 시 +40점
  - 고객사 스펙 매핑 완전성: 모든 항목 스펙 존재 시 +30점
  - 공정 이력 정상 범위: 가열 품질 등급 A이면 +20점, B이면 +10점, C이면 0점
  - 유사 사례 학습 데이터 충분성: 동일 강종·고객사 50건 이상이면 +10점

PENALTY_FACTOR:
  - 검사 항목 결측 1개당: -5%
  - 이상치 플래그 데이터 포함 시: -10%
  - 신규 고객사 (이력 없음): -15%

등급:
  HIGH   (85~100%): AI 판정 즉시 채택 권장
  MEDIUM (65~84%):  품질 담당자 최종 검토 권장
  LOW    (0~64%):   반드시 전문가 수동 검토, AI 판정은 참고용
```

#### 3.4.5 Human-in-the-Loop 프로세스

```
흐름:
  AI 판정 완료 (신뢰도 점수 포함)
      ↓
  신뢰도 ≥ 85%: 자동 승인 후 품질 담당자 알림 (5분 내 이의 제기 가능)
  신뢰도 65~84%: 품질 담당자 검토 요청 알림 → 담당자 확인 후 승인
  신뢰도 < 65%: 반드시 전문가 수동 검토 → 수동 판정 입력

  모든 경우: 최종 출하 승인은 권한 있는 사용자(품질 팀장 이상) 전자 서명 필요
```

#### 3.4.6 수용 기준

1. **AC-AGT-01**: AI Agent의 출하 합부 판정 정확도는 숙련된 품질 담당자 판정 대비 95% 이상 일치해야 하며, 이는 분기별 검증 테스트를 통해 측정된다.
2. **AC-AGT-02**: 모든 AI 판정 결과에 신뢰도 점수(0~100%)가 표시되어야 하며, 신뢰도 65% 미만 시 자동 출하 처리가 차단되고 수동 검토가 강제되어야 한다.
3. **AC-AGT-03**: 납기 리스크 HIGH 판정 시 10분 이내에 영업 담당자·생산 관리자에게 자동 알림이 발송되어야 한다.
4. **AC-AGT-04**: 고객 질의 응답은 평균 5초 이내에 응답해야 하며, 응답에 사용된 데이터의 출처(Heat No., 검사 날짜 등)가 명시되어야 한다.
5. **AC-AGT-05**: 클레임 대응 초안 생성 시 한국어 및 영어 버전이 동시에 제공되어야 한다.
6. **AC-AGT-06**: Human-in-the-Loop 승인 없이 출하 최종 처리가 진행되어서는 안 된다. AI는 판정만 제공하고 확정은 사람이 수행한다.

#### 3.4.7 우선순위 (MoSCoW)

| 항목 | 우선순위 | 근거 |
|------|---------|------|
| 출하 적합성 자동 판단 + 신뢰도 점수 | Must | 핵심 AI 가치 기능 |
| Human-in-the-Loop 승인 프로세스 | Must | 안전·법적 요구사항 |
| 납기 리스크 분석 및 통보 초안 | Should | 영업 가치 높음 |
| 클레임 대응 초안 생성 | Should | 대응 시간 단축 |
| 고객 질의 응답 (RAG 챗봇) | Could | 포털 연동 필요, 2차 개발 |
| 외부 고객사 포털 직접 접근 | Won't | 1차 범위 외, 보안 검토 필요 |

| 재가열 발생률 | ~8% | ≤ 3% | 재가열 건수 / 전체 가열 건수 |
| 온도 이탈 감지-대응 시간 | ~15분 (수동) | ≤ 2분 (자동) | 알람 발령~조치 완료 시간 |
| 단위 에너지 소비 | 기준선 측정 필요 | 10% 절감 | kWh 또는 Mcal/ton |
| 납기 준수율 | ~85% | ≥ 95% | 납기 준수 건수 / 전체 출하 건수 |
| 출하 판정 처리 시간 | ~2시간 (수동) | ≤ 30분 (AI+승인) | 검사 완료~출하 승인 시간 |
| 클레임 대응 초안 생성 시간 | ~1일 (수동 작성) | ≤ 1시간 | 클레임 접수~초안 완료 시간 |
| Traceability 조회 시간 | ~30분 (수동 조회) | ≤ 3초 (자동) | Heat No. 입력~결과 표시 시간 |
